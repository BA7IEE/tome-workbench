# 当前业务不变量

1. **TM 商品身份**：一件实物一个永久 TM，同款不同实物可有多个 TM。外部货号、订单、RMA 和 Agent 都是来源证据。ItemSourceLink 为长期多来源关系，Item.sourceId 仅兼容。
2. **来源与确认**：Agent 只能走通用 ingest session/batch/candidate。所有新机器 Batch 必须提交 v1.2 的 protocolVersion、Skill 与服务端指定 Profile；缺 metadata 的新请求拒绝，legacy 只限数据库已存在且同键同清单的历史事实。Profile 必查项与 Agent 声明项共同进入封批检查，不能由客户端降低。来源 Sold/Shipped、成色、颜色、尺码和金额保留原文，不自动改库存或标准化。普通省略或 `null` 保留已有来源值；只有受限 `sourceCorrection` 能在同步提交 `UNAVAILABLE` 字段检查及原因时清空误填的 `sourceCurrentPrice`，并把依据留在候选修订中。外部 Agent 可在独立 `agentProposal` 中按服务端字段目录提出下拉选择、格式化、翻译和推断建议，但每项必须带置信度及来源字段/图片依据，不能用建议填平 `sourceFacts` 缺项。建议只覆盖标题、现有品牌匹配、一级品类、材质、颜色、尺码、尺寸文本和中文介绍；不得建议本地成色等级、真实性、成本、售价、库存、成交、图片公开权或发布。候选必须人工确认；确认时才采用已展示建议，默认 PAUSED，明确核对可用 AVAILABLE。
3. **候选完整性和身份**：完整性、缺原图、身份冲突不能批量豁免。可接受来源缺项逐候选绑定版本。精确同图只是证据，但必须阻断静默重复建档；同图不同实物要逐件确认和审计。关联已有 TM 不改现有状态、人工资料、价格、批准。
4. **采购与成本**：订单行原价、逐件折后金额、来源当前价、零售价、人民币取得成本独立；未知金额留空，不能互相冒充。没有确认支付/汇率依据不得分摊。TRR 成本规则使用逐件折后金额作权重；任一保留商品缺少正数折后金额即阻断，不得退回原价比例猜测。现金、Store Credit 与退款按确认后的经济支付口径处理。保留人工 businessDecision/possession/TM 关联。采购 Source 生成要求 INCLUDE + IN_HAND。RMA/退款/排除需要明确最终经济支付依据；Sale 成本是历史快照，不能因后续采购修正反改。
4.1 **采购来源默认币种**：`ProcurementSource.defaultCurrency` 只在后续新候选未传币种时补值；既有候选保留已保存币种。更正必须走 `supply` 权限的正式来源命令，带来源版本、`Idempotency-Key` 和原因，并记录前后审计；不得直接写库或借此重写封存批次、订单、TM、库存、成本、成交、账期快照或 TRR 的 Cost/Store Credit 规则。
5. **库存和财务**：同件不得重复售出，item lock、DB 唯一约束、版本保护保留。不明确冲突记 Observation/PAUSED。快速停售不受财务缺项阻塞；人工库存观察不编造收入。未知金额 NULL，不能跨币种合计。financial-journal 和账期保护不放松，对账不是法定财务或自动协议解释。
6. **权限与幂等**：所有写入保留原命令键，相同键不同载荷冲突。重放前重验账户、Session 和角色。业务/Audit/Receipt/Outbox 同事务。登录失效或明确拒绝不能证明之前未知响应的写入未发生。
7. **素材与快照**：原图不可覆盖；预览单独保存。来源 URL 不授予 PUBLIC 权利。图片来源、用途、授权和复核独立。UsePackage/MaterialExport 冻结，下载不等于第三方发布。旧下载重验商品与图片元数据、权利、版本及原字节；INTERNAL 重放重验 finance，默认不带成本、私密文件、内部备注。
8. **TEST 隔离**：仅管理员显式创建/分类 TEST；公开展厅、经营统计、sell 成交投影排除 TEST/删除商品。恢复 TEST 不变 BUSINESS。保留历史交易金额、退款、图片和对账快照；新增清理依赖必须进入当前摘要。
9. **经营待办**：工作台与经营待办共用 /api/work-queue，只读投影，动作回来源模块。已售但仍待 DELIST 的分发记录优先级 100，UNKNOWN 95、库存冲突 90；逾期或缺少下次时间的 FOLLOWUP 询盘也是 90，今天待跟进和新 OPEN 询盘 85，未来 FOLLOWUP 55，明确分发失败 70、资料缺项 50、成交补账 30。询盘按 sell、分发按 publish、补账按 finance 显示，不通过首页泄漏高权限信息。
9.1 **动态资料缺项与审核队列**：渠道 `missing[]` 只从当前 `DistributionTarget` × Channel 读取，不创建或更新持久 `PREPARE` Task；历史 PREPARE 不作为当前待办。所有未批准的正式 TM 都进入同一个分页的 ITEM_REVIEW 队列，不能因当前页面、渠道或批次而遗漏。
10. **字典和稀疏录货**：标准 ID 与措辞快照分开，未知品牌/颜色不自动入字典。唯一性、分类、版本、停用和权限校验保留。未选中的品牌文本阻止保存/筛选，选定取消旧异步结果；空可选字段请求失败不能阻止只填名称。成色采用 VC 五级，不宣称行业统一标准。
11. **操作与恢复**：QuickIntake 仅首触字段，先校验图片；保留完整编辑出口及原文件/命令键。连续录货显式、成功显示 TM；QuickEdit 只改常用商品字段，冲突阻断。原图、询盘、发布、成交和资料导出的未知响应重试不重复写。编辑时禁用控件前取得待保存值，不能让 FormData 丢草稿。
12. **前端表示不改领域**：共享 approveRevision；浏览先只读，显式编辑，保存/取消保留返回上下文。图片立即保存动作与未保存文案独立。缺项原地可修，不能为了短路径移除素材权利/角色/批准证据。对话框真实点击、键盘和手机可操作，不强制点禁用控件。
13. **资料交付与渠道**：DistributionAttempt 是冻结资料针对某渠道的交付、回传、核对和停售经营记录，不是平台执行 Runtime；默认 UI 将其状态解释为待交付、已交付、已确认完成、需要处理、需要核对或已取消。系统根据冻结资料指纹和已有成功/停售事实自动选择 PUBLISH、UPDATE 或 NOOP；待交付、已交付或需要核对的原记录必须先处理，不能靠新 UsePackage 重复发布。UNKNOWN 只能在原记录附核对依据后改为成功或失败，并产生审计。Item 从 AVAILABLE 转为 RESERVED、PAUSED、SOLD、GIFTED、SELF_USE、SUPPLIER_SOLD 或 QUARANTINED 时，按当前周期每个已确认发布渠道建立一个 DELIST；该记录用 `sourceAttemptId` 绑定具体成功 PUBLISH/UPDATE，并以 `delist:<sourceAttemptId>` 去重。恢复 AVAILABLE 不自动重新发布，历史无 sourceAttemptId 的 DELIST 不重写。Listing 只表示已知稳定远端身份；APP 没有 remoteId 时用标题永久 TM 核对，不准写 `MANUAL:TM...`。所有当前成功的 PUBLISH/UPDATE（无论是否已有 Listing）都由 `PublicationHealthService` 按库存、Target、渠道用途/启用状态、供应商 Offer、批准/鉴定、发布图片权利和交易价格复核；不安全时只计划来源关联 DELIST，不调用平台。七天 UsePackage TTL 只限制新的交付，不单独让已确认发布进入待更新。启用 ChannelPrice 时，它是该账号的有效价；没有启用值才回退 Item 默认价，交易价必须大于零且符合目标账号币种。Readiness、预览、草稿、UsePackage 和有效包复核都用同一有效价；不自动换汇、不覆盖 Item。改价、改回默认价或恢复覆盖都会使旧草稿/包按来源与版本重验。分发 Token、领取与租约只保留为受限高级接口，数据库只留 Token 哈希；它们不授权平台登录或操作。AnQiCMS 标准交付合同只读本地脱敏投影：tm_code 是唯一查找键，archive ID 是唯一可回填的远端身份；`condition_grade` 与 `condition_description` 分开，`styleNumber` 是唯一新写入键。售出 identity-only 投影只读 TM、当前状态、Channel 和 archive ID，输出 stock=0 并保留页面，不被历史图片授权或包失效阻塞；真实发布仍由外部 Agent MCP/API 或人工完成，ToMe 不调用外部 API。
13.1 **渠道用途与经营目标**：`Channel.businessPurpose` 是账号经营用途。只有 `TRADE` 可写 ChannelPrice、走 TRADE 的 Readiness/草稿/UsePackage，并成为 `DistributionTarget`；XHS 固定 `CONTENT`，SHOWROOM 固定 `SHOWROOM`。Target 是 Item×Channel 的当前经营意图，不是库存、批准、UsePackage、Attempt、Listing 或远端在线事实；创建/关闭都保留原因、版本、Item lock、Receipt、Audit 与 Outbox。同平台第二个激活 Target 需要明确确认；关闭 Target 不会替代历史实际停售登记，Worker/Sweep 会把仍在暴露的成功资料判为需停售并建立来源关联 DELIST。
13.2 **标准 Handoff 合同**：`tome-distribution/1.0` 只允许当前 Channel 的外部执行方列出待交付记录、取得有效冻结 Package、回填已确认完成或报告待人工处理；取包才记为已交付。机器先从 protocol 取得并校验 Skill/Profile SHA-256，`X-Distribution-Token` 与同一 Token 的 Bearer 头等价。PUBLISH/UPDATE 必须按包的标题、正文、价币种和图片位置（包括 DEFECT）原样使用，交易价必须大于零；未知价格保持 NULL。APP 可在说明永久 TM 核对依据后空 `remoteId` 成功；AnQiCMS 的 PUBLISH/UPDATE 必须回传稳定 archive ID，且其取包的 `platformData` 只承载现有本地 builder 合同。DELIST 可以只交付永久 TM 和 Channel 身份，不得因为旧图片授权失效而阻塞停售。停用或退出 TRADE 的渠道拒绝新的 PUBLISH/UPDATE；仅在还有未完成 DELIST 时可创建 stop-only 会话，且该会话只能看见和取得 DELIST，全部完成后不能再创建。机器 Token 每次请求及每个 Receipt 重放都重新检查会话、创建者启用状态和 publish 权限。`ATTENTION` 会进入 UNKNOWN，标准 Agent 不能再次取包或回填成功，只能由人工在原记录核对；而标准 Handoff 超时或会话死亡只动态投影为 ATTENTION，不自动重发或改写 RUNNING Attempt。薄 MCP 仅有 list/get/report-published/report-attention 四工具，不包含领取、心跳、续租、调度、浏览器或平台操作；旧领取/租约路径默认由 `DISTRIBUTION_COMPAT_RUNTIME_ENABLED=false` 关闭。
13.3 **渠道价与询盘币种**：`Channel.defaultCurrency` 是账号默认币种；AnQiCMS 固定 USD、闲鱼固定 CNY，创建/编辑账号和写入 ChannelPrice 时后端都拒绝违反约束的值。不同币种不能把 Item 金额复制为渠道金额，未知值保持 NULL，不自动换汇。询盘选择配置账号时默认使用同币种有效渠道价；没有同币种有效价时只带目标币种、不填金额。询盘转成交严格保留 `Inquiry.currency`；直接成交选择已配置账号时使用有效渠道价币种（不符合账号要求时回退该账号要求币种），未配置账号才使用 `Item.currency`。只有 CNY Sale 才会自动冻结已确认的 CNY 成本，外币 Sale 的 `cost` 保持 NULL，不能把人民币成本写进外币账。外币结算没有已建 FX basis 时，确认必须以 `FOREIGN_SETTLEMENT_FX_BASIS_REQUIRED` 阻断；本版没有 FX 引擎，也不会改写既有外币 Sale。
13.4 **分发经营投影**：默认分发中心只按激活的 `DistributionTarget` 与历史真实 Exposure 读取当前 Item、Readiness、冻结 UsePackage、DistributionAttempt 和已知 Listing，动态归为 READY（未发布）、BLOCKED（缺资料）、PENDING（待交付）、HANDED_OFF（已交付）、PUBLISHED（已发布）、NEEDS_UPDATE（待更新）、ATTENTION（异常）、NEEDS_STOP（需停售）或兼容的 CANCELLED。已确认发布记录附带当前发布安全原因：批准版本、渠道价、文案或图片变化为待更新；库存、Target、渠道、Offer、批准/鉴定、图片权利或交易价不安全为需停售。它不写入 `ChannelInventoryTruth` 等第二商品真相，不会因此创建 Package、Attempt、Listing、任务或任何外部请求。渠道、状态、品牌、TM/商品搜索必须在服务端排序和分页前完成；Dashboard 的“分发异常”只使用相同 `scope=attention` 结果，不能另算一套数字。
14. **询盘转成交**：普通询盘状态只有 OPEN/FOLLOWUP/LOST；`FOLLOWUP` 必须有 `nextFollowUpAt`，OPEN 可为空，WON/LOST 一律清空该日程。WON 只能由确认成交命令在同一事务中产生。该命令锁定 Item，检查 Inquiry 版本、可售性、历史 Sale 和预留，创建带 channel/channelId 历史快照、`inquiryId` 和原 Inquiry 币种的 Sale，停售、消费匹配预留、更新 Inquiry、写 Audit/Outbox 并为每个成功分发资料代际计划来源关联的 DELIST。金额、成本、费用和到账仍可为 NULL 后补，不能因此跳过停售安全动作。

长期蓝图仍有未实现项，以 [AC_MATRIX](AC_MATRIX.md) 为准。未接外部连接器、在线支付、联网 AI、自动发布、自动退款/分账，默认副作用 OFF。
