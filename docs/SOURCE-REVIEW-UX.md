# 来源资料与单件核对交互

本切片处理候选核对时图片被长说明推后、单件操作缺乏商品身份、查看来源后无法直接返回处理，以及异步弹窗关闭后丢失键盘焦点的问题。保持当前界面风格和领域控制器，不包含列表分页、移动编辑保存栏、待办重排等后续切片。

## 行为与边界

- PC 使用图文双栏，首张原图前置；窄屏全屏单栏，关闭与返回位于独立固定页头，内容内部滚动。
- 名称、来源、原货号、图片数量和缺项摘要常显。Agent 建议默认折叠，摘要保留需重点复核数量，展开后保留值、方法、置信度、依据和说明。
- 完整来源字段、独立来源金额、尺码/日期、撤下图片审计和原始证据继续可查；原文件及当前/撤下图片范围不变。
- 单件处理显示图片和商品身份。普通候选用“核对并归入商品库”，疑似重复继续明确确认另一件实物；二者仍进入既有确认流程，默认待整理，权限和必需确认不变。
- 来源资料中的“返回处理”回到同一候选。关闭或 Escape 返回原列表按钮，不清选择或改页码、滚动；编辑中查来源不丢草稿。
- 不新增 migration、依赖或外部动作，不写生产数据，不修改来源事实、库存、成本、图片权利、历史修订和封印。

## 操作说明

1. 在待确认列表点商品图片，先看图和身份，再核对来源信息。
2. 展开“外部Agent整理建议”核对逐项依据；缺项、身份疑问仍按原要求处理。
3. 要处理单件时点“单件处理”或“核对重复”；查看来源后点“返回处理”继续。
4. 点“关闭”或按 Escape 回到原入口。归入商品库仍须在确认表单中明确核对，查看资料本身不会生成 TM。

## 验收与发布

`v1-item-center.spec.cjs` 使用隔离合成资料，经真实 UI 登录执行；不得用生产商品作夹具。覆盖 PC/手机、键盘焦点、原图尺寸、来源及 TM 不变、人工草稿、返回位置和选择。断言更新仅因普通候选入口语义及建议展开方式变化，不降低重复/缺项/人工确认要求。截图为合成测试页面，不代表真实经营验收。

验证入口依次为 prepare-test、typecheck/lint/build、verify:release、npm audit 和 pack。完整当前结果以 [VALIDATION](VALIDATION.md) 与当前版本 summary.json 为准；不得复用旧源码指纹。合并与部署仍需用户确认已验证 PR head，本文件不构成部署或真实手机 UAT 证明。
