# 兔泥巴日常使用 · 1.0 商品经营中台

## 先看「经营待办」再决定今天做什么
登录后的工作总览会读取同一套经营行动队列；侧边栏「经营待办」可查看完整列表。它不会复制业务数据，而是把已有真实记录投影成下一步动作。

当前会汇总：Agent待确认商品、渠道停售/补资料任务、未解决事实冲突、待跟进客户询盘，以及缺成交额/成本/费用/到账确认的成交记录。渠道停售和事实冲突优先级最高；具体完成动作仍回到商品、询盘或成交模块执行。不同角色只会看到自己有权限处理的敏感事项，例如成交补账不会显示给只读账户。

## 新货先走「快速录货」
登录默认进入商品列表。新到一件货，点击「＋ 快速录货」即可；首次只处理图片、商品名称、品牌、品类、报价、币种、成色和图片来源。尺寸、材质、鉴定、英文和发布资料以后再补，不要求第一次就填完。

快速录货可以一次选多张图片，也可以拖入或粘贴；选错的图片可在提交前单张移除。保存成功后直接打开下一张空表单，并持续显示上一件的TM编号和名称。Ctrl/⌘+Enter可以保存并下一件；需要继续深度维护时点「保存并完善」。

商品列表「更多 → 完整建档」保留原来的整页建档能力；供应商货源接手仍进入完整建档，因为已有来源资料需要复用。测试数据、特殊持有方式、位置、鉴定资料等低频内容也在完整建档中处理。

## 已有商品：常用改动不必打开整页
商品列表行尾「••• → 快速修改」只显示名称、品牌、品类、报价、币种和成色。改价、修正品牌或成色可直接保存；图片、尺寸、鉴定、库存、发布和财务仍进入完整商品页。若同时有人修改同一件，系统会阻止覆盖并保留本次输入。

点击商品名称或图片进入完整商品工作区。完整页顶部只保留「保存」「准备发布」两个主动作，其他低频动作放在「更多」。品牌可输入中英文名或别名搜索；成色、颜色和主要材质使用固定下拉选项。

## 采购来源与订单
资源 → 采购与来源用于记录采购平台、供应商和线下采购。先新增采购来源，再粘贴订单行表格；系统先生成预览，核对件数、来源金额、折扣/运费、包裹和退货/RMA后才确认导入。

导入订单不会自动产生库存。进入订单详情后，逐件确认“实物在手 / 不在手 / 未知”和“纳入经营 / 排除 / 待核对”。只有明确纳入经营且实物在手，才能生成货源候选；已有TM可直接关联。

订单行金额、平台当前价、估计零售价分别显示。人民币取得成本只在有实际人民币支出、已确认批次汇率或明确人工分摊依据时录入；系统不自动换汇。来源成色和来源图片均不等于本地复核结果或公开使用授权。

## 图片就在录货页维护
点击「＋ 添加图片」或拖入图片。已保存图片可看大图、设封面、标记为瑕疵实拍、移出当前展示。原件保留。输入中的商品文字不会因为操作图片而丢失。
图片来源按实际选择自己拍摄或供应商提供。参考图、AI图、授权撤回和过期图片不能通过普通实拍核对流程用于交易。特殊授权及历史管理仍可从「更多素材操作」进入。

## 准备发布不用跳到另一套流程
点击「保存并准备发布」，右侧打开本商品的发布工作区。选择平台账号和使用场景后，系统按已有资料排出内部文案预览。没有渠道时可先新增一次，以后直接选用。

缺少资料时，点击缺项即可定位并展开本页输入框。填写后点「保存商品并重新检查」。没有人工改过的临时预览会跟随已保存资料更新；已经写过的渠道文案保留，不被系统重写。遇到他人更新过的渠道文案，必须明确选择冲突处理方式。

核对标题、正文、选图、瑕疵和价格后，具有复核权限的人员可集中确认一次。自己拍摄的图片不需要重复填写授权说明；供应商图片必须填写实际授权依据。系统仍分别保留商品版本、图片审查和库存检查。

生成后直接复制标题、正文，下载按顺序排列的图片。到实际平台发布完成后，点「登记已发布」录入结果。生成、复制、下载都不代表外部平台已经发布。英文文案不自动翻译。

## 供应商货源、售出和批量操作
供应商持有的商品无需先调货或重拍；展开「货源与实物」即可记录实际供货确认，不虚构锁货承诺。
商品头部可以登记售出、暂停推广。售出先保护库存，金额和成本可随后补；实际平台下架仍需回填结果。
批量操作从商品列表勾选开始：统一修改指定属性，或逐件编辑。修改某件时有并发冲突会独立提示，不覆盖其他人的新数据。

## 测试与正式数据
需要模拟交易时，在新建商品的「货源与保管」中将记录类型选为测试数据。清理带模拟成交的商品使用「清理测试数据」，先核对影响和TM编号；不是删除真实账目或执行退款。原有字典、回收站、测试隔离和中文操作记录继续可用。

## 遇到异常
提交结果待确认时使用页面的继续/核对按钮，不重复新建。重新登录会保留当前输入。修改成功但重新读取失败会明确提示；页面不会把失败任务显示为完成。实际运行边界及验证报告见 README 和 docs/validation/对应版本。

## v1.0：大批外部货源的日常路径
外部平台有大量历史订单时，不要在采购订单里逐件建立商品。先在「待确认 → Agent接入」创建短期导入会话，把一次性Token和协议交给Codex、WorkBuddy或其他桌面Agent。

Agent完成采集后，商品统一出现在「待确认」。正常批次优先使用图片模式全选，一次确认实物在手并批量生成TM；异常商品再单独点「调整」或「查看来源」。每页真实最多100件。

确认TM以后，采购订单退出日常维护主线。以后补图、文案、尺寸、鉴定、询盘、价格、库存状态和成交都从商品库进入；资料没补完不影响商品保持可售。

## v1.0：人民币成本
TRR来源先配置一次来源规则：按订单原价比例分摊、Store Credit计入采购支付价值、每单附加成本¥200。每笔订单再确认实际人民币扣款或人工汇率。

系统先给出全部保留TM的成本预览；有RMA、退货或排除商品时会阻止自动写入，直到人工确认最终经济支付金额。确认后一次写入全部TM成本，商品库和商品页直接显示当前人民币成本。

已经售出的商品保存成交当时的成本快照；后来重新核对采购成本不会修改历史成交利润。
## v1.0：遇到疑似重复商品
待确认卡片出现“疑似已有TM”时，不要直接批量生成。先点“核对重复并关联”：系统会列出强匹配TM及依据；确认是同一件实物后填写/确认TM编号并关联。

关联只把本次来源证据归入原TM，不会覆盖原商品资料。若核对后确认只是图片相同、实际是另一件独立实物，使用“确认新建TM”，并明确勾选同图覆盖确认。
