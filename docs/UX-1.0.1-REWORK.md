# ToMeBoutique UX 1.0.1 重整

本轮只重整操作者路径和信息架构，不改变 TM 商品事实、来源证据、库存锁、成本依据、幂等、审计、图片权利和发布有效性规则。

## 目标

1. 工作台成为默认入口：先处理今天要做的事，不先把用户丢进全量商品库。
2. 商品工作区成为日常经营唯一入口：询盘、预留、成交、暂停、恢复、发布从当前商品直接完成。
3. 旧商品详情退为档案与历史，不再与新版工作区竞争日常动作。
4. 批量操作把隐藏状态显式化；危险动作确认一次即可，不追加无意义的“开始执行”。
5. 候选确认拆开“实物在手 / 纳入经营 / 是否立即可售”，默认生成 TM 后保持待整理。
6. 能登记成交的 sell 角色可以查看成交事实；只有 finance 角色看到金额、成本、费用、到账、退款和合作分成。
7. 询盘与成交优先使用同一套渠道配置，减少自由文本造成的数据污染。
8. 快速录货在创建 TM 前校验全部待上传图片；TM 已创建后任何上传失败都必须明确提示“商品已保存，不要重复录货”。
9. 已发现的已有 TM 候选优先点选，不要求手抄 TM 编号。
10. 发布工作区继续保留后端三阶段安全边界，但用户只感知“保存编辑 → 发布前检查 → 生成资料”。

## 不允许破坏的业务规则

- Agent 不能直接创建 TM、改库存、确认成本、记成交或发布。
- 来源状态不能自动映射本地库存；来源成色不能静默写入本地标准成色。
- 同一实物优先保持一个 TM；重复图片只能作为提示，不能自动合并。
- 库存、成交、退款、成本和发布写入继续要求幂等、版本检查和审计。
- 缺少财务信息不能阻止先执行“已售出/停止推广”的库存安全动作。
- 图片公开使用权、瑕疵披露和批准版本规则不得为了缩短 UI 流程而放宽。
- 历史成交成本快照不得被后续采购成本重算反改。

## 第一批 P0

- 默认路由与导航：首页=工作台。
- 商品工作区把“记录询盘 / 预留 / 登记售出”提升为直接动作。
- sell 角色可查看脱敏成交事实。
- 询盘渠道改用已配置渠道 + 线下/其他兜底。
- 候选批量/单件新建默认 PAUSED，并允许操作者明确选择 AVAILABLE。
- 已匹配 TM 改成直接选择，手工输入仅作兜底。
- 快速录货前置图片校验并显示上传阶段。

## 后续 P1

- 旧商品详情只读化并改名“档案与历史”。
- 发布图片拖拽排序；合并重复的批准/确认表达。
- 采购订单默认只显示待核对/异常件，正常项折叠。
- 成本中心改成“缺什么就处理什么”的异常驱动页面。
- 客户选品草稿持久化并支持刷新/跨设备恢复。
- 批量选择增加可检查的 Selection Tray。
