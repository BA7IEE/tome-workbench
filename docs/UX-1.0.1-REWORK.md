# ToMeBoutique UX 1.0.1 重整

本轮只重整操作者路径和信息架构，不改变 TM 商品事实、来源证据、库存锁、成本依据、幂等、审计、图片权利和发布有效性规则。

## 目标

1. 工作台成为默认入口：先处理今天要做的事，不先把用户丢进全量商品库。
2. 商品工作区成为日常经营唯一入口：询盘、预留、成交、暂停、恢复、发布从当前商品直接完成。
3. 商品链接首先进入 rc.19 只读概览；主动编辑才进入完整工作区，保存和取消返回原商品及原列表/批次。库存、询盘等动作复用同一领域控制器。
4. 批量操作把隐藏状态显式化；危险动作确认一次即可，不追加无意义的“开始执行”。
5. 候选确认拆开“实物在手 / 纳入经营 / 是否立即可售”，默认生成 TM 后保持待整理。
6. 能登记成交的 sell 角色可以查看成交事实；只有 finance 角色看到金额、成本、费用、到账、退款和合作分成。
7. 询盘与成交优先使用同一套渠道配置，减少自由文本造成的数据污染。
8. 快速录货在创建 TM 前校验全部待上传图片；TM 已创建后任何上传失败都必须明确提示“商品已保存，不要重复录货”。
9. 已发现的已有 TM 候选优先点选，不要求手抄 TM 编号。
10. 发布工作区继续保留后端三阶段安全边界，但用户只感知“保存编辑 → 发布前检查 → 生成资料”。

## 不允许破坏的业务规则

- Agent 不能直接创建 TM、改库存、确认成本、记成交或发布。
- 来源状态不能自动映射本地库存；来源成色不能静默写入本地标准成色。
- 同一实物优先保持一个 TM；重复图片只能作为提示，不能自动合并。
- 库存、成交、退款、成本和发布写入继续要求幂等、版本检查和审计。
- 缺少财务信息不能阻止先执行“已售出/停止推广”的库存安全动作。
- 图片公开使用权、瑕疵披露和批准版本规则不得为了缩短 UI 流程而放宽。
- 历史成交成本快照不得被后续采购成本重算反改。

## 第一批 P0

- 默认路由与导航：首页=工作台。
- 商品工作区把“记录询盘 / 预留 / 登记售出”提升为直接动作。
- sell 角色可查看脱敏成交事实。
- 询盘渠道改用已配置渠道 + 线下/其他兜底。
- 候选批量/单件新建默认 PAUSED，并允许操作者明确选择 AVAILABLE。
- 已匹配 TM 改成直接选择，手工输入仅作兜底。
- 快速录货前置图片校验并显示上传阶段。

## 后续 P1

- rc.19 已交付只读商品概览，整合保留；不再回退成默认编辑，也不另造一套档案页。
- 发布图片拖拽排序；合并重复的批准/确认表达。
- 采购订单默认只显示待核对/异常件，正常项折叠。
- 成本中心改成“缺什么就处理什么”的异常驱动页面。
- 客户选品草稿持久化并支持刷新/跨设备恢复。
- 候选已提供只读的已选商品汇总；可编辑的跨模块选择托盘仍未实现。

## 验证映射与旧断言调整依据

- 原 `ux101.spec.cjs` 三项在两种浏览器执行；新增只读详情中的预留/解除真实写入丢回执、同键重试与明确恢复可售组合回归。
- `product-library.spec.cjs` 保留 rc.15–19 的全部原图字节、资料包、只读往返、批次范围与关页恢复用例。找货测试改为明确从商品库登录，首页归属由 UX 用例测试；手机用例名称改为“商品资料库按尺码位置来源及缺项找货，手机日常入口可实际切换”，覆盖全部新导航。
- 原候选确认按钮更新为“批量生成TM”；原文本输入渠道改为配置渠道或“其他”后填写实际名称；同图关联改为选择匹配项。这些只调整已获授权的交互入口，保留真实请求、回执丢失、身份保护和结果断言。
- 手机导航用例明确定位设置工具中的“销售”分组，避免与新主导航同名链接混淆；仍实际点击并验证发布记录可达。新增预留回归按商品 API 的有效预留投影判断：预留后为 1，解除后为 0；原数据库历史不删除。
- 批次缺项与关页恢复同时核对生成商品 PAUSED；七件导入回归明确选择 AVAILABLE 并核对结果，证明在手和可售是两次明确决定。
- Harness 对照 Chromium 自动发现文件和 WebKit 明确执行列表，漏套件即失败；自测验证漏 UX 文件和跳过 UX 用例均被拒绝。

最终结果、数量与日志以 [VALIDATION](VALIDATION.md) 和本版验证目录为准。整合、测试和更新 PR 不等于合并 main、生产部署或真实经营验收。
