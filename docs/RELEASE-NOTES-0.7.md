# 0.7.0-rc.1 · 常规商业后台交互重构

本轮不增加新的业务领域，而是重构日常操作层。目标是让经营人员按“找商品、编辑商品、准备发布、售出”完成工作，而不是理解素材、审核、快照、任务等内部模块。

## 商品列表
- 登录默认进入商品列表；正式商品、测试商品以页签切换。
- 首屏保留搜索、库存状态、品类和商品表格；品牌、成色、颜色、材质等放入“更多筛选”。
- 点击商品名称或图片直接进入编辑。每行只保留一个 `•••` 菜单，准备发布、删除等次要动作收进菜单。
- 批量选择、跨页选择和逐件编辑仍保留；批量修改继续使用相同字典、权限和版本保护。

## 商品编辑
- 顶部只保留“保存”“准备发布”两个主动作；保存并返回、连续录货、详细记录等进入“更多”。
- 页面按常规商品后台组织：名称与图片在左侧主区域；品牌/品类、价格、成色/瑕疵在右侧；尺寸、英文、研究、货源和复核按需展开。
- 新商品第一次保存后立即稳定切换到该商品URL并补齐详细记录入口，不要求刷新页面。
- 图片上传、设封面、标瑕疵、移出展示都在商品页完成；原件、授权和历史记录仍保留。

## 发布与库存
- “准备发布”在当前商品上下文打开，不把经营者送去另一套工作台。
- 渠道草稿、缺项定位、实拍授权、复核、生成使用包、登记人工发布仍保留原业务约束。
- 售出、暂停、恢复等库存动作收进“库存操作”；库存安全动作没有被视觉简化绕过。

## 兼容与安全
- 没有数据库结构变更，没有改变TM编号、测试数据隔离、默认合作归因、成交账目、审计或回收站语义。
- 并发编辑、响应丢失、幂等重试、渠道草稿冲突、图片授权、供应商货源和售出停推继续由原服务规则保护。
- 0.7不接真实平台自动发布、支付或联网AI；生成资料不等于已经发布。

## 验收
- 新增 `ux2.spec.cjs`，验证主动作数量、次要动作菜单以及商品列表不再堆叠按钮。
- Chromium 与 WebKit 都执行0.7界面验收；旧业务回归同步改为通过实际可见菜单完成，而不是访问隐藏控件。
- 自动化耗时不代表人工录货时间；实际经营效率仍以真实商品试用为最终标准。
