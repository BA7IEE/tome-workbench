# 快速录货跨窗口建档恢复

首次新建/更新发送前，先持久化账户隔离的不可变请求、原 key 和阶段；存储失败不发送请求。取得回执后保留已创建身份和已确认字段，图片完成才清理当前录货恢复记录。不会把凭据、Cookie 或 CSRF 写入记录。

重新打开同一浏览器会恢复原输入；未知尝试提供“核对本次提交”，只重放原请求。同窗口或跨窗口都不能用新 key 替代未知载荷。恢复记录限制为自身 Own intake 的 /items 创建或指定 Item PATCH，校验 schema、字段及签名，不能改成其他接口。明确拒绝与未知结果分别记录，不能把已知冲突永远锁成未知。

已知 Item 的图片队列恢复原 File 字节与 key；未落盘图片提示重新选择，允许明确核对后稍后到同一 TM 补图，不假称跨浏览器/清存储也能恢复。

新增真实创建后丢回执、关闭再开、相同 key 核对且只一件 TM 的浏览器案例；轻量单测覆盖发送前存储、跨实例原请求、存储失败零发送和恢复接口限制。尚待本片自身完整 CI。第一片 2b54f9e 的 run 38197506838 已195/195双浏览器通过，只证明第一片，不证明本片。

图片丢回执故障注入保持真实服务器写入。WebKit 的被拦截 multipart 请求不能假定由 route.fetch 保留原二进制；修正为读取该请求 key 对应的持久队列原 File 字节与字段，通过共享真实 UI 登录会话提交同一载荷，真实201后才断掉原浏览器回执。原件 SHA、原 key、401/真实重新登录、无重复图/无重复 TM 的断言保留。不会向浏览器伪造成功响应，也不把传输注入失败当作应用经营失败。新自身 CI 待核对。
