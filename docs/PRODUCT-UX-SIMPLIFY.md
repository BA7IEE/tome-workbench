# 商品 UX 第二批：减少同时出现的操作

本轮在云实例 `/workspace/tome-workbench` 实施，远端 main 经 Git HTTPS 与 GitHub API 两次只读核对均为 `87bc1d7f722b1992b0ad58561da632c8262612d0`（PR #62 已合并）。保留 Ant Design 6.6.5 + ProComponents 3.1.15-5，不使用 Mac。独立分支 `fix/product-ux-simplify-batch2`，只修改前端、合成测试与文档；不合并、不部署，不改 API、权限、数据库、编号或真实商品。

## 实际发现的五个问题

1. 完整编辑页同时出现保存/下载、询盘/预留/售出/发布、来源与三项定位，资料维护主线被打断。
2. 13 图图库每张图同时显示设封面、标瑕疵和移除，动作文字拥挤、点击目标小。
3. 编辑栏的下载在桌面/手机各有一份 DOM，准备发布也有重复入口。
4. 勾选后的批量栏同时露出下载、清单、逐件编辑及更多，手机操作区较密。
5. 取消边界说明重复而偏小；新图片等待商品保存的反馈不够明确。

这些结论来自正确 main 的真实应用、真实 UI 登录与独立 `tome_test` 合成商品，不是静态模型图，也没有登录或修改生产商品。

## 本批完整改动

- 商品库保留直接编辑和卡片/列表切换。页面首要动作仍为快速录入；资料包历史移至页面「更多」。批量栏继续仅在勾选后出现，只露出下载资料、取消选择与批量操作，其余原能力均可在批量操作中找到。
- 编辑栏只突出保存，取消保持可见；下载只有一个入口，放入「更多」。详情来源的主保存已经返回详情，不再显示相同的第二个保存返回。准备发布集中在该菜单。保存当前件、保存并返回、连续编辑与返回上下文保留原合同。
- 单一发布入口的收敛仅针对完整编辑；只读详情继续保留原直接准备发布入口，不削弱浏览页的常用动作。
- 经营状态始终显示在「经营与来源」摘要中，动作按需展开。普通资料、图片、尺寸材质、品牌/品类、报价、成色、中文介绍仍保持原默认可见/展开顺序，英文、扩展资料、鉴定等仍可折叠。新建后会正常显示经营区。
- 点击图片直接浏览原图，单图修改进入该图「更多」。修改菜单明确提示立即保存，移除确认再次说明取消编辑不撤销；取消移除零写入。菜单 Escape 关闭并还原焦点，操作后重新读取/重绘也恢复至原图菜单，图库滚动保留。
- 间距统一为 16/20px，图册提示/分区标题更易读；图片修改目标至少 44px。上传区域明确随商品保存，反馈区分待保存数量、上传中、已保存与失败，不以文字保存成功冒充全部图片完成。

已有图片修改立即生效，新图随表单保存，仍是不同请求、非原子事务。本轮只解释和防误操作，没有新增 staging、媒体版本 token 或 edit-commit 事务。原文件、权限、版本、未知回执及同键恢复依然由既有控制器负责。
