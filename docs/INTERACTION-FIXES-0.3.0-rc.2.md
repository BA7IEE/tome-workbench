# 0.3.0-rc.2：操作阻断修复

本次范围是表单、勾选、上传纠错和提交失败后的恢复，不是新增整套电商功能。

## 已复现的问题

- 必填项缺失时，浏览器阻止提交，但工作台没有明确的文字提示。
- 渠道草稿在服务器保存成功、响应丢失后，重试使用新的请求号，导致版本冲突。
- 图片上传被明确拒绝后，即使修改了来源，重试仍发送旧的来源信息。
- 文本框的标签与内容混在一起，准确识别和辅助操作受影响。

## 修复

- 表单缺项显示字段名，并定位到对应输入；失败保留填写内容。
- 提交期间锁定表单，双击不会发起第二次写入；保存成功与页面刷新失败分别提示。
- 渠道草稿保存与发布资料生成分别保留请求号。结果不确定时可核对原提交，不制造重复资料。
- 修改正文、标题、图片或核对依据后，取消旧确认，需要重新勾选。
- 登录过期可以在原表单上重新验证原账号，不必丢弃输入。
- 上传明确失败允许修正信息重试；结果不确定时仍按原请求核对。
- 扩大复选框及标签的点击区域，支持文字点击、键盘与触摸；全选显示部分选择状态。
- 未核验图片仍不能用于交易发布，但明确提示原因并提供处理入口，没有放宽真实性或授权要求。
- 多步骤弹窗不再在进入下一步时刷新父页面；弹窗关闭事件按所属窗口隔离。

## 验证

`test/browser/interaction.spec.cjs` 包含14条交互旅程，使用真实点击和触摸，不强制点击被遮挡或禁用的控件。响应丢失测试先让真实服务器执行，再切断回执，以测试恢复逻辑。
Chromium运行全部页面回归；WebKit重复交互回归。合成数据只在tome_test中使用。详见 `docs/validation/0.3.0-rc.2/summary.json`。

本次不新增数据库迁移。生产公网部署、业务方验收和基础设施容灾仍是独立条件；浏览器回归不等于所有可能操作均无缺陷。

## 跨浏览器追加复核

WebKit中还复现了：批量复核已经成功，关闭结果窗口后图库仍显示旧状态。根因是上一步排队的关闭事件消耗了新窗口的一次性监听。已改为只处理当前窗口真正关闭的事件，保持原有业务断言，不用强制刷新或放宽测试来掩盖问题。

静态的“已核验”提示不能替代交易前的有效性检查。图片授权过期、被存档或商品售出后仍由后端阻止取用。

切换核验还发现后端版本号仍使用旧的硬编码，导致页面和健康接口的版本不一致。现统一从交付包的 package.json 读取，并增加版本一致性测试。最终切换仍需同时检查页面、健康接口和服务状态。
