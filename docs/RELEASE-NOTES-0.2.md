# 0.2.0-rc.2 修复与交付说明

本版本修复了前一轮尚未闭合的实现，并补齐生产模式容器、迁移保护与验证流程。它没有把20年蓝图未实现的能力改成“已完成”。

## 关键修复

1. 本地启动脚本原先截断且引用不存在的初始化文件。现有完整安装、锁定依赖、待迁移自动备份、安全迁移、构建和进程监督流程；可执行JavaScript语法纳入Harness。
2. Runtime曾声明心跳接口但没有实现，退出后IPC仍保持。现在实现心跳，停止API/Worker后断开IPC，避免残留进程和维护锁。
3. Worker容器探针对UUID使用了text数组，导致正常Worker被误判不健康。改为uuid数组，并实测双Worker健康和异常恢复。
4. 运行账户与迁移账户分开，生产运行检查实际数据库权限、表所有权及每个迁移校验。所有运行实例共用数据库级维护锁，而不是仅判断当前目录PID。
5. 用户等待事务锁期间的权限不能只依赖请求入口：业务写入与幂等重放会重新核对账户、角色和会话。HTTP密码计算改为异步，共享登录限制在PostgreSQL。
6. 商品旧编号面板出现重复渲染，现仅在商品资料页渲染一次。下拉框使用明确可访问标签，不把全部选项并入控件标签。
7. 商品批量归档、尺寸不适用及撤销历史、选品合集、单币种快照确认已补齐可操作界面，并执行浏览器流程。

## 测试变更的依据

旧图片fixture无法正确解码，替换为程序生成的有效合成PNG，没有放宽图片校验。旧测试假定一次失效扫描会处理全部商品；当前Worker按25件分批，随机UUID排序会使该假定偶发失败。测试现在走完整游标周期，仍严格断言商品停售、下架任务、失效包不可用；没有扩大生产批次或把错误状态接受为正确。

旧UI测试中的部分标签与界面不一致，采用统一界面词汇，并增加必填来源说明和明确输入的合成分成比例。没有删除失败场景、增加skip或使用模拟接口代替真实HTTP/PostgreSQL。

## 部署边界

已提供非root、只读根文件系统、双API/双Worker、HTTPS、看门狗、源代码指纹与源码包校验。故障测试只作用于自有合成测试进程和隔离容器。正式域名、真实服务器、异地备份、告警收件人、业务UAT尚未由本次测试代替；生产检查会保留这些待确认项。
