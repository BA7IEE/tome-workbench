# 商品资料库 MVP 日常操作（1.0.0-rc.19）

以下是当前主路径；后文保留较早版本的完整业务工具说明。

点商品图片或名称先打开详情，查看不会进入编辑。大图支持上一张/下一张、键盘左右键、放大、查看原图及下载原图；详情中的上一件/下一件仅浏览本次列表当前页。点击「编辑商品」后修改，保存回详情，取消会询问是否放弃尚未保存的内容；返回列表或批次保留原条件。完整建档、连续编辑和发布工作区仍支持持续保存。

已保存图片上的设封面、标瑕疵、移除会立即保存，取消文字编辑不会撤销它们；新图片随商品保存。库存操作独立确认并生效，金额未知也能登记真实已售，不能通过取消文字编辑撤销库存动作。

只录一件可以「保存并关闭」；需要连续录货才选「保存并下一件」。下载单件资料可直接从详情打开，批量仍从列表勾选；「生成并下载」确认后自动取文件，下载失败直接重试已有资料包。「资料包与变化」可返回原记录页。导入完成后点「查看本批商品」，重置筛选不会切换到其他批次。


各页搜索框、选择框和按钮统一高度与对齐。手机页头的操作位于说明下方，设置等多列表格可在表格内横向滑动查看完整列。蓝色标记当前商品视图，键盘聚焦的原生输入框有蓝色边框。「货源与供应商」里的「手工录货」也直接打开快速录货，不再先跳商品列表。

商品库的「排序」在结果上方，「每页数量」在底部分页栏，选好即生效。搜索、排序、翻页和切换视图都会核对当前填写的筛选；条件变更时从第一页开始，品牌只输入未选择会先提示纠正。展开筛选和勾选商品不自动搜索。条件未变时，排序、页大小和翻页都会保留已选商品；重置只清筛选，保留视图、排序和页大小。手机也可以使用这些控件。

1. 从「商品库」找货。默认只看可售商品；库存筛选可切换全部、已售等。更多筛选支持尺码、箱号/柜号/保管人、来源和缺图/缺价/缺尺码/缺文案。未知金额留空，真实零成本可以是 0。
2. 少量新货点「快速录货」，名称即可保存。完整商品页逐步补尺寸、文案和原图；手机可就地记已售或暂停。成交金额未知时先停售，之后由有权限的人补账。已售退回仍走退回与复检流程。
3. 大批资料从「导入记录」打开本批核对。外部 Agent 使用通用协议上传；来源明确未提供的字段可一次勾选、写本批依据，系统逐件保存。少传原图、疑似同图同件、实物未核实等要按失败原因处理。新批补采保留旧批成员和 TM，不覆盖人工资料。
4. 勾选最多 100 件后「下载商品资料」，或商品页「保存并下载资料」。一包包含中文表格、JSON、逐 TM 文字和原文件。CSV 金额写元（例如 1280.00）；JSON 的 priceMinor/costCnyMinor 写分并注明单位。默认运营参考资料不含成本、内部备注或凭证。财务角色可另选内部完整资料。
5. 「资料包与变化」核对上次整理后哪些商品已售、改价、补图。变化后旧包暂停下载，可按当前资料重新整理。记录只证明整理过资料，不代表平台已发或已下架；来源参考图的外部使用权限仍需单独核对。
6. 批量处理、资料整理或原图上传丢回执时，用原提交继续。关闭页面后回到同一浏览器、同一账号，导入页可继续上次处理；商品原图在该 TM 编辑页恢复；资料导出重开下载即可恢复。可显式结束尝试，但已完成的服务器记录会保留，应先核对再选择。不要清理浏览器数据来重试。未点击保存的文字不是跨设备草稿。

原有销售、待办、采购、资源和账户等在「设置 → 其他业务记录与维护工具」，权限不变；商品页「更多」保留原发布准备入口。无需先配置发布渠道才能录货或整理内部参考资料。

两个人共同使用须访问同一个持久化服务，用各自账号登录。本地 127.0.0.1 演示只在此电脑访问，不能当作朋友手机已连通。公网部署、HTTPS、异地备份和真实双人操作验收仍按 PRODUCTION.md 单独实施。代码仓库和源码 ZIP 不包含经营数据库或原图；本次隔离库备份恢复测试不等于线上异地备份已配置。

# 当前操作与生产边界

本文件保留首版操作说明；0.2.0-rc.2的生产配置、维护锁、Docker多实例、升级和上线条件以 `PRODUCTION.md` 为准。原有本地备份命令不能直接当作正式Compose异地备份服务。

新增可用入口：商品资料页的旧编号/尺寸适用性、批量素材归档、客户选品合集、对账快照、运行状态。

批量归档先上传待归属池，再确认TM号及来源。确认仅绑定实物，不会自动核验真伪/授权。记录不适用必须有依据，可以撤销并保留历史。

对账需要管理员明确登记并启用双方实际约定的比例和依据；没有默认30%。单币种预览发现缺收支或冲突会阻止确认；已经确认的快照不可改写，后续变更用差额更正。

所有外部平台发帖、支付、退款、付费AI和付款仍关闭。公开上线前必须配置实际服务器的备份/告警并完成业务样本验收。

# 运行、升级、备份与恢复

## 本地运行
Node 22.12以上且低于25、Docker Desktop、npm。首次安装需要访问npm和Docker镜像仓库。新目录解压后双击启动工作台.command，或执行 `node scripts/start-local.mjs`。Windows对应.bat，未在Windows真机验收。
脚本创建独立随机.env与data/postgres.env，不覆盖已有配置；启动PG16独立容器，仅绑定127.0.0.1:55438；生成Prisma客户端、执行版本迁移、编译前后端，再同时启动API与Worker。默认地址 http://127.0.0.1:4318 。未安装Docker或端口被其他程序占用时明确报错，不杀进程、不连接其他库。首次启动后另开终端 `npm run setup:admin`，输入内部邮箱标识和姓名，随机初始密码写入data/first-admin.txt（权限600），不印在日志。浏览器登录后修改密码，再安全删除该初始化密码文件。
支持五个固定角色。ADMIN可维护货源、复核、经营账与账户；OPERATOR不能看财务和供应关系；REVIEWER进行商品专业复核；FINANCE记账并查供应关系；VIEWER只读商品。合作方首次用ADMIN或按真实职责分配账户。当前不是可视化自定义RBAC，也没有SaaS隔离。
Ctrl+C停止API及Worker，数据库保留。仅停止数据库可执行`docker compose stop postgres`；不要使用down -v或删除data来“修复”问题。

## 用户操作路径
设置先创建渠道账号（闲鱼、VC、小红书、Carousell等为人工发布；SHOWROOM为系统自有只读展厅）。渠道可保存默认币种、分发模式和不含凭据的受控端点标识；密码、Cookie、验证码、设备 Token 和私有 API Token 不进入本系统。资料不齐可直接新建商品；货源原始记录也可CSV/JSON预览后批量导入，再选择接手建档。来源键建议供应商:货号，编号TM由系统生成。
商品详情编辑材质、尺寸依据、品相、介绍，补原始图片；复核人员单独核验真实性与图片授权并批准商品资料。用途检查仅创建缺项任务，不强迫已齐供应商资料重新拍测；研究非必要时留空。不知道的金额留空，不能填0假装确认。
取用与渠道：选择账号与用途，查看已批准文案并人工改写，冻结使用包，复制文案/下载有序图片 ZIP；系统据资料内容和该渠道历史自动准备首次交付、更新资料或无需重复交付的分发记录，再由外部 Agent、脚本或人工完成平台操作并回填结果。各账号可单独设置渠道报价；未设置时才回退商品默认报价，系统不自动换汇。取得稳定远端 ID/链接才建立 Listing；APP 没有 ID 时，已确认完成的记录仍保留，并以标题中的永久 TM 作为后续核对/停售定位。禁止用 `MANUAL:TM...` 伪造远端 ID。下载不算发布。客户卡不能转作交易发布回执。公开展厅不接收付款。
我方卖出先点“我方已售出”；金额可后补。由询盘成交时使用「确认成交」，它会原子创建 Sale、停售并计划已分发渠道的需要停售记录；不要把 WON 当作普通跟进状态。预留、暂停、隔离待复检、赠与、自留和供货方已售同样会让已确认发布的渠道出现“需要停售”；每条记录对应具体一次成功资料，恢复可售不会自动重新交付。供应商独立卖出、赠与、自留使用各自按钮。外部订单键建议平台:账号:订单行ID。存在冲突时看待核对观察，不凭感觉新增另一笔收入。所有平台停售都须由外部操作者真正完成后回填分发记录；Worker不操作平台账号。
朋友例外先填明确客户标记、原因、有效期，与具体交易匹配；不永久排除该商品。经营账是预览，补实际收入、取得成本、直接费用和到账状态；CostEntry是可追溯明细，供人工核对销售成本，不自动改历史销售数。例外改变需管理员记录实际约定依据。不同币种不求和，不生成30%自动付款。
全额退款且同件完好回收才点完好退回，商品进入待复检；专业复检后恢复可售。部分退款不恢复库存/取得成本；毁损和复杂售后需人工核查，本版不自动分摊。

## 升级与维护
先运行全部Harness并备份。锁定依赖用npm ci；升级依赖单独PR审查和重新安全扫描。已部署migration不修改，新结构增加前向migration。新版API/Worker同版本运行，schema变更先评估兼容性。运行档案reports必须显示实测命令与失败，不把浏览器截图当后台正确性证明。
API/Worker在data/run创建本库进程标记。进程崩溃的标记检查PID不存在后可自动清理；无法判断PID所属则保守阻止，人工核查。不要删标记来绕过正在运行的维护锁。

## 离线完整备份
停止本系统API和Worker，保留PG运行，然后 `npm run backup -- --offline-confirmed`。只备份本地独立库：pg_dump自定义格式 + 原始/派生素材 + SHA256清单。独立容器若不是compose启动，设置TOME_PG_CONTAINER为明确的本项目容器ID。数据文件权限600；备份含客户/账户及经营隐私，不能放公开网盘或发布源码ZIP。环境密钥需另行安全备份，不能跟数据包一起公开；本版不是云端定时备份服务。
只要API/Worker进程标记仍活跃，备份拒绝。确认没有未受控的其他直接写入者，才可声明离线一致。不要手工往运行中的对象目录复制/删除文件。

## 恢复演练（不覆盖现库）
仅使用可信本项目备份，`npm run restore -- /备份目录 tome_restore_check`。脚本校验相对路径与SHA256，创建全新tome_restore_*库（已存在就失败），单事务恢复数据库，素材复制到单独目录；不启动API/Worker，不重放外部动作。不支持覆盖原数据库。
核对Item数量、TM序列高水位、关联、Cost/Sale/Adjustment、原件和预览哈希。确认目标连接、素材路径后，另建关闭外部动作的环境做验证；切换真实业务须用户批准。源码ZIP不含.env、数据库、初始化密码或备份。

## 生产开通边界
这是一套已测的内部首版候选，不是完成74项终态验收的生产ERP。多用户真实营业使用前仍需20件自有服装+20件供应商包袋UAT、实际协议口径对齐、素材权利核查和恢复演练。
公网必须HTTPS、安全Cookie、反向代理同源，不能把数据库端口开放。部署前确认磁盘监控、备份异地副本、TLS更新、访问控制与敏感数据保留周期。Cookie/SameOrigin策略不应因图省事改成全开放CORS。成本/交易敏感字段不得放进公开商品页。
本版EXTERNAL_EFFECTS_ENABLED=true会拒绝启动；付款、退款打款、平台自动发布、真实AI调用没有连接器，不应解锁。示例渠道字符上限不是平台当前规则保证；必须自行按账号实际要求确认。
# rc.5 现金与Credit退款成本核对

来源成本规则启用“Store Credit计入支付价值”，TRR每单附加成本设为¥200。普通订单沿用原成本依据表单；退款订单展开“核对现金与Credit支付、退款”，四项均填订单币种金额，未发生的填0。人民币扣款对应退款前现金支付，不能拿退款后净额推导原始汇率。

明确退款归属时展开逐件退款字段，现金与Credit退款合计必须完全分配。未明确归属时只使用经确认的整单净额比例分摊；不可把“不纳入经营”自动解释为退款或成本消失。归属已排除商品或退款大于该件分摊采购款时先核对，不能为通过校验虚改金额。

保存后重开可看到明细和固定汇率。来源订单/成本规则更新后，重新核对依据再写入成本。旧依据没有固定汇率时也要重确认。退款和成本计算不会改变商品库存；实物退回通过商品状态流程记录。重复提交同一命令键只返回原结果；新命令重算保留历史成本记录，已售交易的成本快照不变。

本版没有自动获取历史月均汇率；实际扣款/确认汇率仍由现有表单录入。不能把此局部修复当作完整的批量商品经营流程已经交付。

# rc.6 外部采集资料核对
在待确认页创建Agent会话后，把接入说明及`AGENT-INGEST-PROTOCOL.md`交给外部工具。中台不登录或采集外部网页。外部工具先声明本批预期商品及必查字段，逐件记录字段是否取得和完整图册文件清单，再上传原文件。收齐声明内商品、文件且尺寸一致后才能封批；来源下架/未提供/仅有缩略图要写明原因。
待确认页点击商品图片直接看全部已保存原图及参数。右上“导入检查”查看最近100个批次及逐件结果。“清单已核对”只表示清单一致；未核验不能当成无遗漏。明确来源缺项的候选批量创建会失败，可在单件处理里接受先建档后补充并记录依据；业务可售状态与资料完善分开。
跨页选择保持在当前浏览器、账号和筛选条件下，最多1000件，修改筛选或退出登录清空。批量以100件分段提交，回执中断保留对话框并使用原按钮重试。失败项保留选择并显示原因；版本变化时先重新核对，再重新勾选，不能强行覆盖别人的修改。
商品编辑页可直接“查看全部来源资料”，不离开编辑器，不清空未保存文字。采购历史显示已经入库的来源图；仅有URL的旧订单仍需外部工具上传文件。再次采集已确认商品可补充来源图，保存在来源层，不能自动取得公开权利或改动人工维护的商品。

## 导入后的图片识别
商品库内部封面与图片数量包含未归档参考图，便于识别外部采购商品。参考图在商品库可见不代表已经获准公开发布。缺项件单独建档后，该件从批量选择移除，其他勾选保留。真实业务试用记录应放在本机私有data目录，与tome_test及合成自动化证据分开。

## 来源资料与本地确认值
商品中出现“来源品牌”或“来源成色”表示已保存平台原文，尚未成为本地标准选项。编辑页在品牌、颜色和成色附近直接展示来源记录与品相说明。品牌需核对后选择已有字典或由管理员新增；成色等级按实物核验结果选择，平台描述不会自动代选。已有人工品牌/成色优先显示，重新导入来源不会覆盖维护结果。历史商品补资料应使用带版本的普通商品维护接口，不直接写数据库。

新增平台或门店来源前，按docs/MULTI-SOURCE-DESIGN.md核对原文保留、字段转换、币种、Credit与费用规则。默认币种仅在新候选未传币种时采用；后续漏传不会改掉已有候选币种。TRR的200元政策不能套给其他渠道。

## v1.1 标准 Agent 接入

创建短期导入会话后，只把一次性 Token 通过受控渠道交给负责采集的人或 Agent。接入方必须先读取 `/api/agent-ingest/protocol`，校验返回 Skill 和本来源 Profile 的 SHA-256；Profile 不匹配、协议主版本不兼容或标准版本低于 1.2 时停止，不要靠旧脚本猜测写法。

推荐交付仓库内的 `tome-ingest` 命令，或把薄 MCP 地址 `/api/mcp/ingest` 配给受控 Agent。两者都只可创建批次、导入订单、写候选、查状态和封批；来源图仍须用 multipart 上传。不能把 Token 放入 `.tome-ingest-state.json`、脚本、截图、日志、数据库备注或聊天记录。状态文件只帮助同一台机器以原请求和原幂等键恢复未知结果。

Profile 的必查字段由服务端与 Agent 本次 `requiredFields` 合并。来源没有提供时写 `UNAVAILABLE + 原因`，不能删除检查项、填零、用常识补齐或把来源字段直接解释为本地库存、成色、成本、售价、成交或公开图片权利。封批前先看完整性报告；blocker 未清零不能封批，非阻断来源缺项仍须在人工候选确认时逐件说明。

## v1.1 标准分发交付

把分发 Token 仅通过受控渠道交给对应 Channel 的外部执行方。默认接入是仓库的 `tome-distribution` Skill 或 `/api/mcp/distribution`：只可列出待交付记录、取得冻结 Package、回填已确认完成、报告需要人工处理。取 Package 时必须传幂等键，它会将记录记为“已交付”；同键未知响应使用原请求和原键恢复，不要另建资料或猜测平台状态。

外部执行方只能使用包中给定的 TM、Channel、标题、正文、价格/币种和图片顺序，不能隐藏瑕疵图、补商品事实、改价或把推断写回主档。APP 没有稳定 remoteId 时留空，并在确认说明留下永久 TM 的核对依据；禁止 `MANUAL:TM...`。AnQiCMS 外部 MCP/API 如果真实返回 archive ID，回填该 ID。`ATTENTION` 会把原记录变为需要核对，之后必须由运营人员在原记录人工确认成功或失败。

停售 `DELIST` 可能只给永久 TM 与 Channel 身份，不会重新拼装旧发布包；这使旧图片授权失效也不会阻断停售。分发 Token、领取和短租约仍是兼容高级接口，不是默认流程。不要在 Token、状态文件、日志、备注、MCP 参数或资料中记录 Cookie、密码、验证码、真实账号或平台页面步骤。完整字段和端点见 [DISTRIBUTION-HANDOFF-CONTRACT](DISTRIBUTION-HANDOFF-CONTRACT.md)。

## v1.1-rc.3 渠道报价、分发和成交

商品页「发布资料」前可在“各渠道报价”按具体账号填写明确金额和币种。AnQiCMS 的交易资料需要 USD，闲鱼需要 CNY；系统不会给出实时汇率或把一个账号的金额写到其他账号。改价、切回默认报价或恢复覆盖后，旧草稿/使用包会要求重新核对，先读取最新 Readiness 再生成新包。

商品库的「批量确认当前资料」先显示每件预检阻断项，再逐件批准；「批量渠道价」接受 `TM编号 金额` 的粘贴行；「批量生成分发计划」先按目标渠道筛 READY，只有当前仍合格的商品会生成使用包和分发记录。系统根据资料内容与该渠道既有完成记录自动判断首次交付、更新资料或无需重复交付；任一件失败都查看该件结果，不用刷新、重开一批或假定平台已执行。

销售中的「商品分发」只显示渠道的待交付、已交付、已确认完成、需要处理、需要核对和需要停售的经营记录。UNKNOWN 必须进入指定账号按标题永久 TM 核对**原分发记录**，再填写依据将它改为成功或失败；FAILED 才能复用原记录重新交付。商品已售但停售尚未回填优先级最高，APP 没有 Listing 也一样；进入对应渠道完成实际操作后登记结果。当前没有真实平台 Connector 或 AnQiCMS API 调用；本地 Spike 资料读取不改变这一点。不要在这里填写 Cookie、密码、Token 或真实账号资料。

## v1.1-rc.4 AnQiCMS 本地 Spike

目前 ToMe 只提供 AnQiCMS 的本地 Spike 资料合同；外部 Agent 的 MCP/API 或人工可取得交付资料后自行完成站点操作，它不是站点登录入口，也不会调用 AnQiCMS。PUBLISH/UPDATE 的合同保留永久 tm_code、USD 渠道价、最多 9 张 Gallery 图片、其余正文图片和公开 SEO 字段；没有 archive ID 时执行方只能先按 tm_code 核对，不能用标题或 MANUAL:TM 占位。

售出后的 AnQiCMS DELIST 合同要求已有 archive ID，并明确要求未来执行方把 stock 置 0、页面保留、显示 SOLD、不开 Checkout。当前必须由人工完成任何站点操作并回填真实结果；不要将 Cookie、密码、Token、真实账号、真实正文或客户资料放进 Channel、分发会话、日志或测试。字段与本地验收边界见 docs/integrations/ANQICMS-CONTRACT.md。

## rc.9 日常操作
商品库“重置/清除筛选”保留正式/测试范围、图片/列表视图、排序和每页数量。勾选后选中商品有标记，批量栏随页面滚动停留；取消选择可清空本次跨页选择。手机图片视图在常用手机宽度下并排展示两件，原文件不变。未填写售价显示“尚未报价”。
行尾更多菜单可点击外部或按Escape收起；快速修改能查看来源品牌/成色，仍需自己选本地字典。“完整商品页”会检查未保存输入，取消放弃则留在原窗口，确认放弃才离开。
待确认状态选择“全部”可同时查待确认、已归入TM和已排除，各件显示对应处理状态。没有结果时使用清除筛选、查看已归入TM或进入商品库；空列表不会允许勾选本页。待办无结果可进入全部事项或回商品库维护。

## rc.10 少绕路的询盘与候选处理
在已保存商品的工作区，顶部“记录询盘”填写渠道、客户内部标记和沟通摘要；不必退出商品编辑。报价可留空。询盘写入成功后，未保存的商品文字仍留在编辑器，需按原“保存”操作另行保存。回执丢失时原窗口重试，使用原命令键，不重建询盘。
经营待办中选择“客户跟进”，点击“去跟进”只显示该条询盘。更新后可回客户跟进待办，或查看全部询盘；「确认成交」才会原子产生 Sale、停售和下架计划，普通跟进/未成交不会。rc.11起操作页面支持全量筛选和分页，精确链接仍可定位单条记录。
待确认PENDING范围支持批量操作；查看全部、已归入TM或已排除时不再提供无效的勾选动作。已归入TM保留导入时提示作为历史资料，后续维护进入对应TM。返回候选列表或保存并返回会恢复原来源、关键词、状态和视图。

## rc.11 批量与长期维护
- 商品库勾选→批量定价：对照图、TM和成本逐件填价；空白表示尚未报价。核对后进入执行结果，失败项保留原因和原请求，成功项不重复提交。
- 商品库勾选→创建客户选品：保留最多40件图文选择，先预检全部商品。缺项件进入完整商品页后“保存并返回”；全部合格再生成合集。未获得图片公开权利、未确认资料或当前不可售仍会阻断。结果待确认时先原内容重试，不能直接重新开一批。
- 采购历史→集中确认成本：先筛选来源和采购月份，跨页选订单，明确填本月采用汇率及出处。已有依据/退款/退货/未归入TM的订单不会套用新批次依据；点击“核对本单依据”处理。预览逐件分摊后另行确认写入。批量对话框关闭前应核对结果；关闭或刷新会丢本次客户端操作进度，已写入业务记录保留。
- 商品工作区→经营记录：原地查看询盘、成交、发布和成本摘要；进入完整记录前仍检查未保存商品输入。跟进询盘填写本次新增沟通，展开历史可核对旧内容。并发冲突保留输入，核对最新记录并勾选确认后再提交。
- 成交、询盘、发布页面支持渠道、商品、日期等筛选和翻页。成交合计代表全部匹配记录，不只是当前页；可分别导出当前页与全部匹配。日期按北京时间自然日，结束日包含当天。
- 渠道“修改 / 停用”需管理员操作。停用不会替代第三方下架确认；历史快照保留。无有效对账规则时先建立草稿，规则激活仍由既有确认流程控制。
本机升级先停止本项目集群，执行离线备份，再用`node scripts/migrate-safe.mjs --local`获取维护锁并应用加法迁移；不得在活跃实例旁直接迁移或重置真实库。

## rc.12 选品异常恢复

选品生成后遇到网络断开，先点「恢复上次提交内容」，核对名称与商品，重新勾选确认后重试。不要反复另建合集。已停用的原渠道只为恢复显示；不代表允许在停用渠道创建新的资料包。分次加入按已有草稿与新选择去重后的40件限制。草稿仍仅保留在当前页面会话，关闭或刷新前请处理未知结果。

## rc.13 网络中断与登录失效叠加

如果提交后网络中断，随后提示登录失效，请使用「重新登录并保留输入」。建档继续点「核对上次提交」；询盘保留原提交内容重试；图片窗口点「重试未完成图片」。原图和来源以首次提交为准，后改来源不会覆盖结果未知的上传。首次明确校验失败的图片仍可修正后重传。不要用关闭窗口、刷新或新建记录代替核对。

## rc.14 查询重置

从某件商品或待办进入记录页，「重置」只清空搜索条件，仍查看原商品或原记录。「查看全部」才切换为同类全部记录，正式/测试范围保持。两个操作都保留返回入口，来自待办等页面的入口显示「返回来源页面」。


## 商品库的新控件

选中商品后，下载商品资料、导出清单、逐件编辑直接显示；定价、修改属性、登记交接、暂停推广、删除等在「批量操作」中按账号权限显示。品牌必须从搜索结果选中；只输入未选中时会提示修正。行尾「•••」可快速修改，弹层支持外部点击和 Escape 收起。

商品页左侧整理图片和介绍，右侧维护归类、报价与成色；按需展开尺寸、来源、鉴定和英文资料。填写已知内容就可保存。保存并下载资料仍要在资料包对话框核对本批用途和参考图片，下载不会自动发布。

本机更新仍用原启动器，不新建业务数据库；本版没有新增迁移。升级后以原账号使用 `http://127.0.0.1:4318/`，不要把测试端口的合成商品当作经营数据。


## UX 1.0.1 日常路径（rc.19 之上）

登录先看工作总览。商品库仍是找货与资料维护入口；导入记录按批核对；销售展示本账号可见的成交记录，完整财务仅财务权限可见。其他业务工具保留在设置。

商品先浏览详情，点击“编辑商品”才改文字资料。询盘、预留、售出可以直接在当前商品操作；暂停需填写依据，解除预留后商品保持暂停，复核后再恢复可售。录货默认保存并关闭，连续录货另选“保存并下一件”。图片不合格式或过大时先修正再建档；已创建后若上传失败，按窗口提示重试或从同一浏览器打开该 TM 继续，不能重新录一件。

批量导入先检查已选商品汇总，确认实物在手及经营去向，再选择待整理或直接可售。默认待整理；明确选择可售需已有实际核对依据。来源缺项仍逐件留说明，身份和原图阻断不能批量绕过。网络中断或关页后从“继续上次处理”恢复原状态决定和命令，不能以刷新重开新批次代替核对。

本次仅整合和验证 PR，未更新本机经营实例或 main。保护分支为 codex/backup-rc19-bfffa5c 与 codex/backup-ux101-1783947；需要对照旧代码时创建独立工作区，不重置或覆盖现有业务资料。任何后续升级仍按原维护锁和离线备份流程进行。

## 保存期间返回页面

修改商品后等待“已保存”且保存按钮恢复可用再离开；“正在保存，请稍候”表示页面仍在处理回执。自动化也必须等待这一前提，不能把数据库已写入当作页面操作完成。成色回归通过延后真实回执核对该保护，不改变现有商品数据或保存实现。

## 登录 CI 诊断

reports/browser-login.jsonl 记录点击前控件状态、请求/响应出现时间、状态码、表单 click/submit/invalid 计数和关闭状态；失败同时检查独立 ready 请求与 browser server 存活。ready=200 包含服务器真实 SELECT 1。reports/browser-login-server.jsonl 记录服务端收到/完成/关闭时间。不记录输入、Cookie、CSRF、请求/响应正文或 pageerror 原文。失败摘要同时输出到 CI 日志，下载 artifact 慢时可直接查日志。

### UX 1.0.2 本机草稿

客户选品会按当前登录账号保存在本浏览器。关闭页面后从客户选品重新进入即可恢复，恢复时重新读取服务器商品；不是跨设备同步。生成结果待确认时，先恢复上次提交内容并重试，保留原命令键，不能清空浏览器存储来重复生成。共享电脑上仍应退出账户并使用独立系统账户/浏览器配置保护本地数据。

批量参数最终确认后会立即执行，结果窗显示逐项进度；失败或结果待确认仍通过原按钮重试。来源接手尚未经过参数确认，因此结果窗保留一次明确确认。发布图片可以拖动，也可通过上移/下移/指定第几位操作；排序需要保存草稿，仅影响发布选图。
