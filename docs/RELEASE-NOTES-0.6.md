# 0.6.0-rc.1 · 单页商品工作区

## 这轮改变什么
默认进入商品列表；点击商品进入同一张可编辑工作区。核心信息为商品名称、图片、描述、品牌、价格和成色。尺寸/材质、英文、研究和鉴定作为可展开补充，不再把系统内部模型当成必经操作步骤。

图片随建档一起上传；在原页面预览、设封面、标瑕疵和移出展示，失败时可核对回执，商品输入不丢失。参考、AI、撤回或过期的图片仍受原保护。

点击「保存并准备发布」在旁边编辑本渠道图文。缺项直接定位到本页字段；修改后原地保存和刷新检查。未人工编辑的临时预览可随资料更新，手工文案不会被重填。普通核验合并为一个明确确认入口，后台仍分别保存商品批准版本、图片审核、渠道文案和不可变使用包。

生成、复制、下载、登记人工发布结果均可在当前工作区完成。没有调用真实平台接口；系统不会把领取资料记录为已发布。售出或暂停可以在工作区头部登记。供货方持有的商品可就地补录实际供货确认，不要求实物经手。

同一商品的不同渠道草稿独立保存。网络回复中断可续办，不重复建档或生成；并发改稿显示冲突，必须明确处理后继续。保存并返回也保存当前尚未提交的渠道草稿，不悄悄抛弃输入。

## 工程变化
新增StudioController仅编排现有业务能力；复核由共享approveRevision实现，保留权限、版本、图片一致性、审计和Outbox约束。整体元数据与核验图集摘要用于防止过期审查。原有图片复核也在取得商品锁后重新读取当前状态。
界面分为字段布局、素材动作、渠道工作区、库存动作四个文件；逐件和批量编辑继续使用同一字段解析器及版本校验。没有数据库结构变更，没有放宽普通删除或测试隔离规则。

## 验证口径
studio.spec.cjs覆盖从新建到使用资料、缺项原地补充、供应商货源、不同渠道、并发修改、回复丢失、原地登记售出与发布、实际文件选择器和手机布局。原有回归因可展开区域移动而使用真实summary点击，不跳过测试、不强制点击隐藏控件。
自动操作的秒数不是人类处理商品的耗时；不能据此承诺“一件商品一分钟”。用户操作效率以实际商品试用为准。
本版本的完整执行结果位于docs/validation/0.6.0-rc.1/summary.json和verification.log。源码指纹不匹配时禁止打包。局部检查通过不能代替完整回归和实际部署。

## 交付边界
本轮是内部经营工作区重构；不代表公网域名、服务器配置、跨主机容灾、外部支付/自动发帖/联网AI及长期蓝图全部完成。现有素材格式仍为JPEG、PNG、WebP；没有伪装成已接入视频或任意附件。
