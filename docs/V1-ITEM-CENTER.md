# ToMeBoutique 商品经营中台 v1.0

## 唯一核心对象
系统以每一件实际经营商品 `TMxxxxxx` 为中心。采购订单、物流包裹、RMA、供应商、外部平台和 Agent 都只是商品的来源、证据或使用记录，不是日常经营主对象。

一件 TM 商品可以在资料不完整时进入经营。资料完整度用于提示后续完善，不作为“能否销售”的固定流水线。

## 四层结构
1. **外部采集接入层**：Codex、WorkBuddy 或其他桌面 Agent 使用短期 Token 提交来源事实。
2. **待确认候选层**：保存原始字段、图片、修订历史和标准化建议；不产生正式库存。
3. **TM 商品事实层**：人工批量确认后生成永久 TM 编号，维护库存、资料、素材、成本和多来源关系。
4. **销售使用层**：发布、询盘、预留、成交、退货、客户选品和对账全部引用 TM 商品。

## 关键边界
- Agent 不能直接创建 TM、修改库存、登记成交、确认成本或发布商品。
- 来源平台的 `Sold / Shipped / Canceled / RMA` 永远只是来源事实。
- 来源成色、颜色、尺码等不会静默写入本地标准字段；来源事实保留在证据区。
- 未识别品牌不会阻断商品入库，标准品牌可后补。
- Agent 图片进入中台后持久保存，但默认是内部参考素材，不自动取得公开使用权。
- 同一 TM 可以通过 `ItemSourceLink` 关联多个来源；旧 `Item.sourceId` 仅保留兼容。

## TRR 成本口径
TRR 第一阶段按已确认经营规则计算：

`经济采购价值 = 退款前现金支付 + 已使用 Store Credit - 现金退款 - Credit退款`。

在成本依据中填写四项明细（均为订单币种）后，服务端计算并保存最终经济支付，原始明细进入不可变的依据修订。不提供明细时可直接确认最终净额；两者同时提交必须一致，不能从已扣退款的净额再扣一次退款。Credit同等计入支付规则须由来源配置启用。

经济采购价值按本单最终保留商品的订单原价比例分摊；每张订单另加人民币 ¥200 附加成本，并在最终保留商品之间平均分摊。

若提供逐件退款归属，先按原价比例分摊退款前采购价值，再按原采购汇率仅冲减对应商品；逐件退款总额必须与两种退款之和一致。跨订单归属、归属已排除商品或单件采购分摊不足以抵扣退款时阻止写入，不能把差额转嫁其他商品。没有归属时仍按经确认的整单净额比例分摊。排除商品与退回实物的复杂分摊仍须人工核对，不自动识别自留件成本。

优先使用实际人民币扣款推导有效汇率；没有实际扣款时使用人工确认汇率。存在 RMA、退货或排除商品时，不自动猜退款结果，必须人工确认本单最终经济支付金额后才允许写入 TM 成本。

实际人民币扣款须对应退款前现金支付。rc.5确认时固定汇率并记录来源订单/规则版本；后续退款不从变化后的来源净支付重算汇率。无RMA但存在退款记录时同样要求确认最终净额，确认值0是有效金额。旧依据没有固定汇率时需重新确认；来源订单或规则更新后也需重确认。不同币种调整不能直接合计。自动取月均汇率尚未实现，不能宣称已经按月自动折算。

成本确认后写入 TM 的当前人民币取得成本。售出时复制当时有效成本到成交快照，后续成本重算不得反改历史成交利润。

## 日常经营路径
默认一级入口是：**商品库 → 待确认 → 待办**。

大批来源商品由 Agent 进入“待确认”，每页真实处理最多 100 件；正常商品以批量确认为主，异常件才单独调整。确认后订单退居“采购历史”，以后长期维护都围绕 TM 商品进行。

线下一两件商品继续使用“快速录货”；已有 TM 的图片、文案、尺寸、鉴定、询盘和状态可长期逐步完善，不要求一次做完。

## 不属于 v1 自动行为
v1 不内置 TRR 网页机器人，不绑定任何 Agent 产品；不自动登录外部网站，不自动判断图片公开授权，不自动把平台状态改成本地库存，也不自动猜 RMA 后的退款和实际汇率。
## 候选身份防重
大批多来源导入时，“同一件实物只有一个TM”优先于导入速度。候选图片与已有商品图片SHA完全一致时，系统只提示疑似同件并阻断静默批量新建，不自动合并。

人工确认后可以把候选归入已有TM；系统只增加来源关系、采购订单行关系和必要的内部参考素材，不改变已有TM库存、成色、售价或人工资料。若只是不同实物共用同一来源图，必须单件明确覆盖重复警告后才能生成新TM。
