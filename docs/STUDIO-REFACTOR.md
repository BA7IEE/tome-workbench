# 商品工作区重构 · 0.6

## 本轮验收任务，不以功能数量替代体验
1. 手工录一件商品：同一页标题、价格、品牌、成色、图片、描述，只有标题是建档必填；其他按需要展开。
2. 保存并准备发布：仍在同一工作区，缺资料直接定位到本页输入；授权、复核和文案确认集中在发布侧栏，不要求往返素材/商品/渠道页面。
3. 一批实拍统一预览、选择、确认公开使用权；参考图、AI图、过期或撤权图不得被批量冒充可售实拍。
4. 有现成资料的供应商商品无强制拍摄或实物经手步骤；供货确认不可虚构。
5. 文案不从审核状态推断丢弃：可用当前未批准资料生成明确标记的内部预览，正式取用仍需明确人工核对并保存快照。
6. 网络回执丢失后原地重试、不重复建商品/审核/文案包；修改不覆盖其他人的新版本。
7. 实際商品发布仍在相应平台完成；内部生成不能显示已发到平台。
8. 商品列表首屏看到商品，不被大面积过滤器和说明文占满；手机、键盘可操作。

## 参考与取舍
- Shopify公开商品操作：标题和已有内容直接录入、保存；详情页组织商品与渠道。https://help.shopify.com/en/manual/products/add-update-products
- Shopify字段说明：不同商品不要求填写全部资料。https://help.shopify.com/en/manual/products/details
- IBM Carbon表单：复杂编辑用整页、可见标签、错误直接定位；反复参照商品时采用侧栏。https://carbondesignsystem.com/patterns/forms-pattern/

以上是交互参考，不复制其全部交易规则。兔泥巴一物一品、素材权利、默认合作、未完备可保存、人工发布回执规则保持。

## 实现边界
使用现有Nest/Prisma与命令框架，不换框架或重写数据库。新增集中复核命令须与原审批共享规则，记录审核人/版本/所选素材。后台权限、状态和原件保护不能为了减少点击而取消。
新界面纳入Chromium和WebKit主流程回归，不使用强制点击，不沿用旧页面的通过数假称新体验已验证。只使用隔离tome_test合成商品验证。

## 发布时间边界
本地升级必须先验证交付包、备份并核验，保留现有数据。不启用真实外部发布/支付或公网配置。没有实际运行、视觉检查和业务操作证据，不标记交付完成。

## 最终视觉与交互复核
手机视图除检查无横向溢出外，还检查核心卡片的实际可用宽度，避免内容缩成窄条但仍算测试通过。保存区保持紧凑，用户名、退出入口与版本保留。
WebKit重复操作复现了缺项定位使用动画滚动时，紧接着点击刷新偶发未执行。将关键任务定位改为立即滚动，不用动画延迟阻碍下一步；相同测试连续重复10次通过，随后仍需完整双浏览器回归。没有通过改成强制点击或放宽断言掩盖问题。
