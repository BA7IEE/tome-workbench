# 0.3 运营可用性开发记录

## 本轮来自源码及实际流程的缺口
- 日常维护要求输入研究/属性JSON；单条货源也要求JSON。
- 同语言渠道预览复用同一文案，没有持续保存的渠道草稿。
- 商品列表只有基本搜索，没有图片浏览、缺项筛选和批量处理。
- 单件商品图片需逐张上传/复核，发布包默认导出WebP，不方便手工平台上传。
- 部分复制入口直接读历史包，未重新核验资料是否过期。

## 交付目标（仍须测试，不等于已通过）
- 图片/列表双视图、现有全库编号/品牌/名称搜索与状态筛选、当前页选择、CSV导出、逐项有结果的批量处理。品类和缺项的全库筛选本轮未实现。
- 分组填写商品字段；研究资料逐条录入、扩展属性键值编辑；不要求运营人员写JSON。
- 图片多选上传、逐文件结果和原幂等键重试；看大图、排序、归档、明确授权复核。
- 渠道工作区：保存可不完整的草稿、不同渠道模板、选图排序、事实变更提示。
- 生成有效发布资料后，标题/正文分开复制、JPEG图片包、手工发布结果登记。
- 普通字段货源表单、CSV/表格粘贴导入、明确预览、按来源复用建档。
- 首页是缺项与任务入口，不是营销口号或系统实现说明。

## 数据与边界
独立开发目录，不修改当前运行的dist；仅使用tome_test进行破坏性自动化验证。
新迁移只前向增加，原件/历史发布/交易不删除；测试通过后再备份并更新原目录。
模板生成不是联网AI；不自动鉴定、伪造年份、发布外部平台或激活真实分成规则。
发布/复制仍检查有效版本、库存、供货和图片授权；提升效率不以撤销安全要求为代价。

## 验证边界
新增渠道草稿、图片选择/归档/JPEG导出等由真实HTTP与PostgreSQL集成用例覆盖。浏览器沿用并更新既有13条回归旅程。额外浏览器用例写入及只读页面取图的工具调用遭安全检查拒绝，未绕过；不把未执行的新增浏览器旅程记为通过。没有运行本轮新的公网/跨地域生产演练。

货源列表已增加真实服务端分页与搜索，旧接口的500条兼容响应不用于新版日常操作入口。
