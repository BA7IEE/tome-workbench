# 多来源商品中台：边界、接入约定与扩展路线

本设计把未来平台、供应商文件、线下门店视为不同来源。不能预先穷尽所有平台字段；目标是新来源接入时不丢原文、不改库存核心、不覆盖经营维护，也不因字段未知而强迫编造。

## 一件实物，一个经营主档

TM代表独立实物，不是订单行、平台商品页或平台SKU。订单、物流、退款、平台状态和来源图片都作为证据关联。采购来源与销售渠道是两个角色：同一平台将来既可以买货也可以卖货，但对应的来源凭据、销售账号、权限和操作记录不能混为一套状态。相同SKU或图片不构成自动合并依据；一件TM允许有多份来源，不同实物允许来自同一平台链接。

日常经营只围绕TM维护：名称、标准品牌、品类、尺码、材质、实物成色、描述、售价、人民币成本、持有/库存、询盘和销售。没有来源订单也能录货；缺项提示和能否经营分开，交易/发布各自保留必要规则。

## 三份资料有明确分工

| 资料 | 保存内容 | 谁可以改变 | 经营用途 |
|---|---|---|---|
| 原始来源证据 | 原字段名/值、嵌套对象/数组、图片、原币金额、URL、采集时间与修订 | 外部工具增加来源修订 | 查原文、追溯，不直接决定库存 |
| 接入后的通用来源字段 | 品牌原文、来源品类/成色、尺码、材质等，以及逐项转换依据 | 每个来源的外部适配器提出；中台接收和核对 | 候选预览、批量确认、缺项提示 |
| TM经营资料 | 稳定字典ID、人工维护说明、实物与销售事实 | 有权限的经营命令，带版本与审计 | 搜索、筛选、日常维护与销售 |

“来源成色：Excellent”和“我们验货后选择的成色”可以同时存在。不同来源的Excellent、A级、九成新不能仅凭字面相近当作同一种标准。后导入资料不能覆盖已维护的主档。

## 接入器负责理解来源，中台负责统一约束

外部Agent或脚本可使用公开/已授权接口、文件、页面等获取资料。采集不进入经营系统。每个接入器将来源字段转换为相同候选协议，同时保留原始资料；中台不增加针对每个平台的库存表、商品表或采集按钮。

以下为合成映射示例，不代表已接入这些真实业务：

| 信息 | 平台A的原字段 | 平台B的原字段 | 门店文件字段 | 提交通用协议 |
|---|---|---|---|---|
| 品牌 | brand_name | designer.label | 品牌名称 | brandRaw |
| 品相等级 | condition | wear.grade | 店员描述 | conditionRaw |
| 品相细节 | condition_details | wear.notes | 瑕疵备注 | sourceFacts.conditionDescription |
| 展示尺码 | size | measurements.display | 页面展示尺码 | sourceFacts.sizeLabel |
| TRR 品牌/标签原始尺码 | tag_size | brand_size | 吊牌尺码 | sourceFacts.foreignSize；缺失则 UNAVAILABLE + 来源侧原因 |
| 额外信息 | collection_year | fabric.panels[] | 票据号 | sourceFacts中按来源命名保留；原始资料完整放rawPayload |

已有sourceFacts允许嵌套额外字段；不要把所有细节强塞到一个备注，也不要为每个平台加一套数据库列。常用于搜索、筛选、报表的字段，经明确业务需求后再提升为受控字段。当前额外字段可查阅，但不具备任意字段高级筛选能力。

建议接入器在rawManifest.adapter中记录name、version、sourceSchemaVersion、mappingVersion，在sourceFacts.mappingEvidence中记录目标字段、原字段路径、原值和变换说明。这些位置目前会被原样保存，**尚没有内置映射规则引擎、专门的元数据校验或规则编辑器**。变换含糊时保留原文并提示；不能把推测标成已确认。

## 完整性按来源清单核对

每种来源先定义自己能提供的资料清单，再提交预期商品键、逐项采集状态与图片清单。来源没有、采集失败、规则未识别、人工尚未确认是不同情况，接入器要说明原因；当前协议只提供CAPTURED/UNAVAILABLE及reason，进一步的错误分类尚待扩展。

当前COMPLETE仅证明声明清单内已收齐，不证明远端无未声明字段。新平台接入必须抽查原页面/文件与保存资料，覆盖分页、多商品订单、失效详情、不同图片角色、退款与缺项。未知字段保留，超出上限显式报告，不能静默截断。

图片保存收到的原文件、实际尺寸、SHA和来源。缩略图不能放大冒充原图；原图不可得要记录原因，图片公开使用权单独确认。

线下来源没有网页时可用手工录货或OFFLINE_IMPORT。当前结构化capture要求HTTP(S) pageUrl，不适用于无网页的纸质单据；这种情况下保留原始文件/资料并标记完整性未核验，不伪造网址。文件型证据标识是后续协议扩展项。

## 身份、修订与冲突

- 接入身份按来源ID和externalKey隔离；同来源还需在外部键中纳入账号/店铺、订单行或独立实物标识，不能只用可能复用的SKU。
- 相同幂等键和相同内容可重试；确定是新采集版本时新建批次，稳定商品键不变。
- 当前稀疏更新保留已有来源值，来源修订和人工TM资料各自独立。纠错/撤回旧值不能靠漏传字段表达，当前需显式核对，尚无通用字段撤回协议。
- 多来源对同一字段有分歧时并列保留证据，人工决定本地值；当前支持逐来源查看和不覆盖主档，**尚无逐字段多来源对照/一键仲裁界面**。
- 同图仅提示疑似同件。归入已有TM只能增来源关系与必要参考证据，不能改变既有商品的库存、售价、成色和批准记录。

## 成本是来源政策和订单依据，不是平台固定公式

TRR每单200元、Credit视作现金是当前经营者针对TRR选择的口径，不能默认套给新来源。新来源启用前单独核对币种、附加费、折扣/退款口径、现金与抵用额度价值、分摊方法，并保存确认依据。采购订单金额、平台当前价、估计零售价、取得成本和销售收入分别保存。

目前实现原价比例分摊采购净额、均摊订单附加费、人工确认汇率/人民币扣款与特定退款归属。数据模型中的Credit配置当前默认true；**该默认值不代表新来源已确认现金等价，接入验收必须显式设置政策**。更复杂的按重量/包裹费用、分层折扣、可用性不同的积分、混合税制需要后续规则扩展。

当前金额仅支持协议列出的六种两位小数币种，不能宣称任意币种已支持；日元等小数位不同的币种应先扩展金额模型和测试，不能套用统一乘除100。历史成交成本保持当时快照，不随来源修订反改。

## 当前实现与下一步

| 能力 | 当前状态 |
|---|---|
| 多来源配置、通用机器接入、无订单候选 | 已实现 |
| 原始/额外字段、修订、原图与采集清单 | 已实现，有协议上限 |
| 一件TM关联多来源、来源更新不覆盖人工资料 | 已实现 |
| 常用字段旁呈现来源原文 | rc.8实现；未知品牌仍不自动建字典 |
| 映射版本元数据的原样保存 | 现有扩展字段可承载，尚无专门验证/编辑器 |
| 新来源自动全量发现与采集 | 外部接入器职责，中台未内置 |
| 多来源逐字段冲突对照、规则批量审批 | 后续实现 |
| 任意币种/税费/积分和分摊规则 | 后续实现 |
| 全部历史订单完成 | 未完成；当前真实验收仅两单13件 |

每接入一个新来源，先用一小批独立样本证明：原文保留、字段映射可追溯、未知值不猜、来源间不串键、重试不重复、确认不覆盖旧TM、钱与库存边界不变，再扩到批量。

## rc.8本次发现并纠正的跨来源假设

异构来源验收发现并修复两处：新候选漏传币种时不再固定CNY，改用来源默认币种；无订单候选关联已有TM时使用数据库既有的REFERENCE关系类型，避免500错误。没有放宽数据库保护约束。测试中的另一平台/门店为合成数据，不等于已经接入第二个真实平台。
