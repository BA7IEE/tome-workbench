# 0.4.0-rc.1：手工优先的商品管理

## 本轮改变
此前商品建档、查看、编辑、素材、资料确认被拆成多个入口，操作者需要先理解系统模型。0.4改为常规商品后台路径：列表 → 新增/编辑整页 → 保存 → 准备发布或记录成交。数据底层的来源、版本、权限、库存和审计不变。

商品列表默认表格。搜索、品类、库存、持有方式、资料确认、发布记录、排序和分页在服务器端处理，不是只过滤当前页。图片视图可切换。跨页选择最多100件，切换筛选会清空选择，避免误操作；选择仅保留在当前浏览器页面会话。

手工新增、现有商品维护、批量逐件编辑使用同一套字段与校验。只有名称必须先填，其余按已知情况保存；研究与扩展资料折叠。商品图片可以在录货页面选择，保存时逐张上传，默认不授予公开使用权。

提供保存、保存并返回、保存并新增下一件；多件编辑时提供保存并编辑下一件。返回列表保留筛选和页码。供应商来源资料可直接带入，但不会把供货报价自动当作售价或采购成本。

## 失败后的真实状态
商品档案先保存，图片分别上传。图片失败时明确显示档案已保存、哪些图片未完成；再次保存不会新建第二件商品。请求结果不确定时保留原请求和内容，先核对后继续；不会因编辑了新内容就把旧回执对应到新输入。

并发修改显示服务器值与本次改动，人工核对合并。未修改字段采用服务器最新值；排队图片保留，不因刷新表单丢失。未知金额不填成零，供货/赠与不伪造收入。

## 验证范围
`test/browser/operations.spec.cjs` 新增手工录货、连续录货、供应商包袋、跨页选择与逐件编辑、图片和建档回执中断、多用户冲突、手机触摸以及完整手工发布至售出流程。
Chromium和WebKit均由完整Harness执行。发布证据由 `npm run verify:release` 生成，源码指纹一致才允许打包。报告存在不代表当前代码已验证，必须查看本版本 summary.json。
