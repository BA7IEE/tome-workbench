# 商品管理最小闭环与全系统裁剪

2026-10-22，基线 main `004eef6ed299b8cb52c630e3698588acb0e95752`。
范围来自用户对整个系统 UX 的要求；四张截图是验收样例，不是范围边界。
本候选不合并、不部署、不读取或修改生产经营数据。

## 第一性目标

保管可识别的商品和原始资料，明确哪些货可以卖，取用适合渠道的资料，
实际卖出后停止继续销售。用户不需要经营记账或先学习内部模型。

正常闭环为：来源/导入 → 人工确认入库 → 查找/修改商品 → 准备上架或下载资料 → 标记售出。
入库不是发布批准，库存状态不等于渠道在线事实；现有库存状态语义保留。

## 全部可达页面的决定

| 路由及子流程 | 决定 | 理由与调用边界 |
|---|---|---|
| items：列表、图片、新建、编辑、详情 | 日常默认入口；合并编辑工具，移除成本显示 | 名称即可建档；版本、原图与未保存恢复保留 |
| dashboard、tasks | 作为需要处理事项入口；删除补账投影、统一总数与落地范围 | 来源用条、商品用件、动作用项，不构成库存漏斗 |
| imports、candidates | 合并为导入路径；确认入库直接显示，批次作为历史上下文 | 预检分组后按件执行原确认命令，不自动批准商品 |
| sources | 保留供应商货源、表格来源及已有来源关联 | 不把来源价格、成色或库存状态当本地事实 |
| procurement：订单、来源、物流、退货 | 保留只读来源及在手核对；退役手工经营成本操作 | 原始采购金额仍是证据，缺失可如实保留 |
| 商品素材、intake | 单件上传为主；批量补图保留独立入口 | 文件名不自动绑定商品；原图和用途/公开权独立 |
| 商品 AI 效果图 | 有内容才在浏览页展示；上传仍走素材管理 | 不作为实拍封面或公开使用权证明 |
| distribution、商品发布工作区 | 对用户称上架；发布检查在实际准备上架时执行 | 保留 TRADE Target、真实报价、授权图片、批准、外部执行和停售回执 |
| listings | 渠道身份历史，移出日常商品操作 | 没有稳定远端 ID 的发布仍由原 Attempt 事实保护 |
| sales、商品售出动作 | 统一成交事实视图；无需金额/成本/费用记账 | 原售出事务、预留消费、重复销售保护和 DELIST 保留 |
| inquiries | 独立客户跟进记录，移出商品常驻按钮 | 不作为录货和卖货前置条件；已有数据、跟进和权限保留 |
| collections：创建、查看、下载 | 独立客户资料包，移出商品批量菜单 | 已有冻结分享与下载合同保留；普通资料下载复用现有导出 |
| financial-history、settlements | 按原 finance 权限只读历史；移除账务编辑和结算创建界面 | 不删表、记录、快照；既有受保护恢复 API 保留 |
| trash、测试数据清理 | 保留独立危险操作与恢复 | 不破坏已有成交、成本、预留和远端暴露事实 |
| dictionaries | 设置内管理；普通颜色不匹配不能阻断入库 | 仅匹配已有词条或别名；未归类原文留存，不新造或错配字典 |
| settings：账户、用户、渠道 | 按角色分离配置页 | 不新增权限，不把管理员界面下放给普通运营 |
| operations、jobs、audit | 管理维护入口 | 后台失败任务与卖货待办分开；重试、审计与证据保留 |
| /showroom | 保留公开展示合同 | 仍只展示已批准且有效资料，不增加付款或自动库存承诺 |
| Agent 接入配置、HTTP/MCP/CLI | 技术配置移出日常动作 | ingest 与 distribution 机器身份和稳定合同不扩权 |

## 统一交互与删除范围

- 日常导航为商品、导入、上架、设置；保存后可从全部库存状态找到商品。
- 商品浏览只突出编辑、取资料/准备上架，以及实际库存变化。
- 批量编辑共享任务选择、价格表、属性控件和逐件结果；删除独立定价/渠道价/
  属性/位置的顶层按钮与旧模块。资料下载包含清单，不再单独维护重复导出。
- 删除独立发布缺项按钮；准备上架自动显示缺项，原发布命令仍是最终校验。
- 删除成本批处理、财务编辑、合作结算创建的客户端代码与调用，不新增“关闭记账”兼容开关。
- SALE_FINANCE 从工作队列范围、SQL、前端类型、筛选和仪表盘加总中删除。
- 历史账务 API 继续承担既有数据查阅、不可变快照和受保护纠错/恢复，不能据 UI 退役删除这些约束。
- 批量预检不是授权豁免：漏传原图、清单矛盾、身份重复、版本冲突和未完成接收单独阻断；
  来源已注明无法取得的资料按组明确接受，并逐件绑定版本及原始原因。
- 未匹配颜色保留原文和待归类提示；不把 Burgundy 猜成红色，不把组合描述猜成单一颜色。
- 弹窗使用视口内宽度，长名称/错误可换行；关闭、返回、提交及原请求恢复都须可操作。

## 验收与保留理由

必须覆盖正常 90 件批量确认、两种截图颜色、风险隔离、混合成功失败、同键并发/
真实丢回执重试、保存后找回、375/390 宽、关闭返回、无隐形记账必填、
无补账待办、无失效导航以及原发布/停售/权限/恢复回归。
旧 UI 测试的财务编辑/独立菜单期望应改为新闭环，不能删除后端财务历史、
退款/恢复、字典身份、图片公开权、库存一致性等保护测试来凑通过。

四张原始截图已从各自 Library 身份 materialize 到执行环境并查看像素。
它们没有给出生产 90 件的逐项缺失字段，因此不推断这些真实字段；
预检必须从当前候选证据读取实际原因。生产版本与实际经营验收仍未核实。

## 售后回收与批量行级处理的收口

- `inventoryReturnedAt` 是独立实物回收事实，不是新库存状态，不改旧 `returned` 全额退款语义。
  新 `202610220023_inventory_return_fact` 只加一个可空时间、不可覆盖/财务痕迹守卫，以及活跃库存占用唯一索引；
  保留旧 Sale_complete_return、全部金额、原Sale、当前Cycle、审计/回执和旧迁移哈希。
- 回收沿用原 finance 权限（管理员/财务），未扩展到普通运营；复售仍需 review。
  普通运营有管理员处理提示。新增受控端点仅接受未经账务维护的版本1、无收退款事实的成交，
  自动取得成本快照原样保留；已记账成交继续原全额退款回收路径。
  回收只进 QUARANTINED；复检后可售并允许新Sale，原DELIST和历史销售不删除、不自动上架。
- 批量报价逐行包含/跳过；未知价/不同币种默认不写，用户填有效金额后可纳入，提交前显示有效与保留数量。
  一件缺报价不能阻塞其他有效行，不猜汇率或用零补空。
- 库存更改按动作显示字段：预留/解除/复检先明确“下一步”，不先索取随后会丢弃的原因。
  新价格表复用 Foundation 适配器，保留原准入守卫。
