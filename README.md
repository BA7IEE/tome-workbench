# 兔泥巴 ToMeBoutique · 商品资料库

**版本：1.1.0-rc.4，标准 Agent 采集、标准资料交付、轻量分发记录、首批运营动作与本地 AnQiCMS Spike 合同。当前事实见 [CURRENT-RELEASE](docs/CURRENT-RELEASE.md)，不等于业务验收或正式部署完成。**

围绕永久 TM 统一管理商品、原图、来源和日常库存动作。采集、平台发布和 AnQiCMS 建站由外部工具完成。保留原有业务模块供需要时使用。真实验证入口为 `docs/VALIDATION.md`；长期74项要求与当前实现的区别见 `docs/AC_MATRIX.md`。

## 日常入口

一级入口为「工作台 / 商品库 / 导入记录 / 销售 / 设置」，销售按账号权限显示。首页进入工作总览；商品库仍默认可售商品图片，切换库存筛选可看全部、已售、暂停。按尺码、实物位置、来源、资料缺项找货；少量新货仍用快速录货，只填名称也能保存。

导入记录按批处理，明确的来源缺项可集中核对并逐件留依据；身份疑问和未传完整的原图仍需处理。商品库勾选后直接整理中文表格、文字、JSON 和原图，或在商品页「保存并下载资料」。再次取用前通过「资料包与变化」查看已售、改价、补图；下载不代表平台发布。

待办、采购、复核和资源等原有入口仍可从设置中的「其他业务记录与维护工具」进入，权限和业务约束不变。操作说明见 [OPERATIONS](docs/OPERATIONS.md)，MVP 范围见 [MVP-RC15](docs/MVP-RC15.md)，本版界面迁移见 [ARCO-RC16](docs/ARCO-RC16.md)，来源 Agent 接入见 [协议](docs/AGENT-INGEST-PROTOCOL.md)，分发 Agent 只按[标准交付合同](docs/DISTRIBUTION-HANDOFF-CONTRACT.md)取得冻结资料并回填结果。

商品库、完整编辑及快速录货/修改字段已采用 React + Arco Design。批量低频动作收在「批量操作」，商品页提供保存与保存并下载资料。其他业务页面保留现有实现，资料和权限规则不变。

rc.17 整理商品库控件：搜索区同排对齐，排序在结果上方，每页数量与翻页统一放在底部。排序、每页数量和视图切换即时应用当前筛选；筛选不变时保留跨页选择。手机保留完整控件，详见 [商品库交互](docs/CATALOG-RC17.md)。

rc.18 清理全系统遗留样式：移除六份旧 CSS，统一由 ui08.css 加载主题、原生控件和 Arco 样式。导入记录与业务记录的筛选区统一对齐，手机标题与操作分行，表格保留可读列宽并在内部滚动；采购记录的边框、间距及商品视图选中态恢复正常。货源页「手工录货」直接打开快速录货。范围与验证入口见 [界面清理](docs/UI-CLEANUP-RC18.md)。

rc.19 调整日常操作流程：商品默认打开浏览详情，集中展示大图、尺码、成色、报价和按权限可见的人民币成本。从详情明确进入编辑后，保存回到同一件商品，取消保留离开确认；连续维护及完整建档仍支持留在工作区。原图支持连续查看、放大和下载；资料包确认后自动下载。快速录货可保存关闭，已完成批次直接查看本批商品，筛选重置保留批次。详见 [商品浏览与维护](docs/PRODUCT-FLOW-RC19.md)。

UX 1.0.1 在以上功能之上提供商品详情内的预留、成交和恢复动作；候选生成 TM 默认待整理，明确核对后可选直接可售。运营账号可看成交事实，财务字段仍受独立权限保护。快速录货先校验图片再建档，保留原图、中断恢复及保存关闭。整合范围、历史保护和测试映射见 [UX 1.0.1](docs/UX-1.0.1-REWORK.md)。

## v1.0 商品中心

v1.0把永久TM商品作为唯一日常经营事实中心。外部Agent先进入「待确认」，批量确认后才生成TM；采购订单、物流、RMA和平台状态退居来源历史。大批外部货源主路径为「Agent采集 → 待确认批量处理 → 商品库长期维护」。

1.0.0-rc.2新增「经营待办」投影：不新建第二套任务真相，而是从候选、商品任务、事实冲突、客户询盘和成交收支缺项实时汇总下一步动作，并按业务风险排序。首页工作总览和侧边栏待办共用这一队列。

Agent协议见 `docs/AGENT-INGEST-PROTOCOL.md`，架构边界见 `docs/V1-ITEM-CENTER.md`。本版将 Agent 采集标准化为经校验的 Skill、来源 Profile、薄 MCP 和确定性 CLI；新机器批次必须携带 v1.2 的协议、Skill 与服务器 Profile 元数据，不能用漏传字段降级成 legacy，已存在同键历史批次才保留旧合同。它们都只调用既有 `/api/agent-ingest`，不能直接创建 TM、改库存、记成交、确认成本或发布。分发侧以 [Distribution Foundation](docs/DISTRIBUTION-FOUNDATION.md) 和[标准交付合同](docs/DISTRIBUTION-HANDOFF-CONTRACT.md)准备冻结资料，并记录发布资料、更新资料、停售资料的交付和经营状态；标准 MCP 只列出交付、取冻结包、确认完成和待人工处理四项工具，外部 Agent、脚本或人工才完成平台操作。没有稳定远端 ID 也能确认完成，但不会伪造 Listing。首批运营动作见 [Real Operations](docs/REAL-OPERATIONS.md)：从 AVAILABLE 进入预留、暂停、售出、赠与、自留、供货方已售或待复检时，已分发渠道会产生绑定具体成功资料代际的需要停售记录；恢复可售不自动重新交付。渠道报价按账号生效并冻结到使用包。AnQiCMS 的 [本地 Spike 合同](docs/integrations/ANQICMS-CONTRACT.md) 已冻结 USD、archive ID、图片和售出保页语义；实际发布仍由外部 Agent 的 MCP/API 或人工完成，ToMe 没有 HTTP Connector 或外部副作用。

1.0.0-rc.5补充现金与Store Credit等值的退款成本核对。可用四项支付/退款明细计算净额；明确属于某件商品的退款只冲减该件。确认汇率固定保存，来源变化要求重新核对，历史成交成本不反改。接口约定见 `docs/contracts/costing.md`。自动抓取月度汇率仍未实现；rc.11已支持跨页选单集中确认成本，汇率及支付依据仍需人工确认。

渠道报价以 Channel 账号为单位：AnQiCMS 固定 USD、闲鱼固定 CNY，其他渠道用账号的 `defaultCurrency`。跨币种时金额保持空白，由运营明确填写；ToMe 不自动换汇或把一个币种金额照搬到另一个币种。

## 已覆盖的工作

采购来源/订单/订单行/包裹/RMA归集、货源预览导入、供应商及供货条件、正式建档与永久TM号、旧编号、渐进补资料、批准版本、原件和授权、批量素材待归属池、按用途缺项与有依据的不适用决定、使用包、人工上架/下架回执、选品合集、询盘、库存预留与售出、朋友交易例外、成本和退款、完整退回后再售、按币种对账快照与更正、审计和运行健康。

商品状态不等于交易收入。未知金额不是0。领取资料不等于平台已发布。供应商自行售出不生成我们的收入。AI仅有人工导入候选，不会自动联网或付费。

## 在当前Mac本地使用

要求 Node.js 22.12–24、已启动的Docker Desktop。在项目目录执行：

```sh
node scripts/start-local.mjs
```

也可双击 `启动工作台.command`。默认打开 `http://127.0.0.1:4318`。本地启动为2个API、2个Worker和进程级恢复；Ctrl+C停止应用但保留数据库。升级前先停止旧实例；检测到待应用迁移时，启动器先做本地离线备份，备份失败则不升级。不要把SRVF的环境文件复制进来。

首次新安装另开终端执行 `npm run setup:admin`。随机密码只保存在 `data/first-admin.txt`，首次登录后修改。不要将该文件、`.env`、`data/`、数据库备份或测试账户打包给他人。

## Linux部署

入口为 `Dockerfile`、`compose.production.yaml`、`deploy/Caddyfile` 和 `docs/PRODUCTION.md`。正式数据库账户与迁移账户分开，运行容器非root且根文件系统只读。正式域名使用HTTPS；当前localhost演练证书不等于已验证公网证书。

**默认只是单台主机上的冗余应用进程。数据库、磁盘、主机仍然是单点。** 跨主机/数据库故障切换、异地备份与运维告警必须独立配置并验证，不能靠修改一个“高可用”开关实现。

## 开发和验收

```sh
npm ci
npm run db:generate
node scripts/prepare-test.mjs
npx playwright install chromium webkit
npm run harness:full
npm audit --audit-level=high
```

集成测试只重置专用 `tome_test`；浏览器测试依赖其合成数据。故障测试只终止自己创建的进程。恢复演练会创建新的 `tome_restore_*` 数据库，不覆盖旧库。不要并行运行会重置同一测试库的两份套件。

`harness:full` 包含脚本语法检查、类型检查、lint、构建、单元测试、Harness负向测试、真实数据库集成、浏览器、进程故障注入、全模型恢复和静态守卫。生产容器演练单独运行；不把已有报告当成新代码已经通过。

## 1.0.0-rc.6 外部采集资料接收与核对
系统不内置采集器。外部Agent/脚本通过通用协议提交商品、字段与图片清单，后台显示完整性核对结果，拒绝缺少预期商品/原文件或实际尺寸不符的封批。来源本身缺项须注明原因；旧导入无清单标为未核验，不追认完整。
待确认支持当前账号/筛选条件下跨页选择最多1000件，每100件分段提交；版本冲突、疑似重复或明确缺项保留逐件原因。商品、候选和采购历史可直接查看已持久保存的来源原图及完整参数。再次导入只丰富来源证据，不覆盖人工商品或候选建议。见`docs/RELEASE-NOTES-1.0.0-rc.6.md`与`docs/AGENT-INGEST-PROTOCOL.md`。

## 1.0.0-rc.11 全系统操作审查修复
经营待办、成交、询盘、发布记录先完整筛选再分页；成交合计与全部导出使用同一全量条件。询盘每次跟进保留历史，旧窗口必须核对版本后才能继续。
商品工作区可原地查看经营记录，采购→商品→采购保留筛选与页码。商品库支持批量定价及看图创建客户选品，集中预检缺项后回商品补充；批准与图片权利规则保持生效。

渠道支持版本化修改和停用，历史资料包不改写。来源页面展示来源名、原货号和图片；运行历史折叠，图片归档可搜索商品并查看原图，对账缺少有效规则时直接说明前提。
操作与验收映射见`docs/SYSTEM-REVIEW-RC11.md`。最终测试和打包结果由`docs/VALIDATION.md`记录；不代表真实平台销售或公开部署验收。

## rc.12 选品恢复修正

分次加入商品按合并后的40件上限核对，超限保留原选择。生成结果未知时持续保留原命令键，可以用「恢复上次提交内容」还原后重试；误改内容或渠道随后停用不会解除重复生成保护。

## rc.13 中断后登录恢复

提交回执丢失后，即使随后登录失效，建档、询盘和图片上传也继续保留原请求身份。上传窗口支持原位重新登录，原图、来源字段和未完成队列保留；重新登录不代表上次操作未成功。

## rc.14 记录筛选与返回

成交、询盘和发布记录的「重置」只清搜索条件，保留当前商品或单条记录及返回入口。「查看全部」解除记录范围，但保留正式/测试类型和返回路径，避免切到另一类数据。
