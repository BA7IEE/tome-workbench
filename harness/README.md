# Harness
A small engineering control loop, not an autonomous production operator.

`npm run harness:check`: verifies essential files, isolated DB/test guard, no real effects by default, pure domain boundary, immutable migration hashes, fixed dependency versions, no skipped tests and new browser server isolation. Machine output: reports/harness.json.
`npm run harness:selftest`: baseline plus eight in-memory mutations prove gates reject unsafe changes. Does not modify project data.
`npm run harness:full`: compilation, lint, builds, 16 domain unit tests, mutation checks, real HTTP/PostgreSQL journeys and browser tests, then static guards. Exact counts are generated by the actual run, not hardcoded pass claims.
The tests use only `tome_test`; its reset guard is checked before TRUNCATE. Only synthetic data is inserted. Browser fixture credentials stay inside ignored data/browser-fixture.json and must not be shipped or attached to reports. Browser traces are off to avoid persisted auth secrets.
Applied SQL has a hash in sealed.json. Generate initial seal with `node scripts/harness.mjs --seal --acknowledge-baseline-change`; after deployment add migrations instead of altering/resealing historical files. Red gates are resolved by fixes and tests, not turning them off.
Static gates do not replace UAT, legal/commercial signoff, live connector verification, restore drills or a security penetration test.
